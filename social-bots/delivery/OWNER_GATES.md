# Owner gates — current interpretation under LEAD-047

G-LEAD releases offline code repair/integration under FINAL_RUN.md. It does not release the gates below. A task's external_gates list describes what its LIVE proof requires, not a reason to block its safe code and fixture tests. Keep one concise gate dossier and continue other released work.

- G-HOST: actual persistent owner-controlled host, local filesystem/locks, native scheduling, installation permission, sleep/reboot behavior and secret-safe Git/client access. Verify where tools execute; a Mac UI is not proof the tools run on that Mac.
- G-LEAD-LOOP: actual authorized recurring/event lead execution with repository read/write and a real reviewed next assignment. An idle chat and a worker-written 'lead' comment do not qualify.
- G-MODEL-V04: the exact new fixed five-call divergence batch needs fresh explicit owner approval plus canonical scoped lead manifest. The old one-call authorization is consumed; excluded duplicate remains excluded.
- G-MODEL-RUNS: separately budget generation/review/specialists and unattended development invocations. Current interactive coding permission does not grant unlimited product-model calls. Lower models count against the same appropriate parent budget. No API-key/PAYG fallback.
- G-ACCOUNTS: the owner allowed necessary existing-account reuse or a suitable necessary account/email using the actual verified Unsubscriber Google Cloud alias mechanism. Reuse first, prove ownership/route/necessity, keep MFA/consent as exact owner actions and secrets outside Git. Do not invent the alias service or create unrelated accounts merely to show activity.
- G-PUBLISH: explicit persona/account/content/effect-count grant for any post, reply or message. Deletion/correction are separately scoped; UNCERTAIN never silently retries.
- G-MEASURE: genuine compatible raw observations and completed declared windows, not synthetic metrics or borrowed baselines. Missing data stays missing.
- G-CULTURAL: an attributable actual review method/event over exact final content. Automated review cannot claim human endorsement.
- G-SPEND: no new spending is authorized. Missing free/subscription entitlement is a blocker, not permission to buy capacity.

Before asking the owner, resolve all available facts locally or through permitted connected reads. Produce one machine-readable record per gate: requested action, artifact IDs, exact namespace/route/host aliases, maximum attempts/calls/effects, zero-spend limit, expiry, actual owner-approval reference, lead-manifest reference, observed capability, next command/action. Never log secrets or invent authorization.

Request template (NOT approval): approve run <id> on verified host <alias>, using provider <route> for artifacts <ids>, frozen inputs <hashes>, maximum <N> calls and <M> effects, no automatic retry, zero new spend, expiry <time/bounded completion>. Until the owner explicitly approves and required lead manifest exists, prepare only.
