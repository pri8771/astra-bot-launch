Goal: create a truthful cross-platform analytics model without pretending unlike metrics are directly equivalent.

Required:
- raw event/metric retention;
- normalized semantic categories (reach, view, completion, save, share, reply, click, follow/conversion where available);
- platform/source/time window/account/persona/content/experiment IDs;
- missing/unavailable distinct from zero;
- metric provenance and collection timestamp;
- derived metrics record formula/version;
- every normalized metric carries a known semantic kind (`cumulative_snapshot`, `delta`, `gauge`, or `rate`) when the platform mapping knows the semantic, including supported-but-missing observations; unknown/unmappable semantics remain explicitly unknown rather than silently defaulting;
- aggregation MUST be semantic-aware;
- cumulative snapshots must never be naively summed;
- delta summation must reject/deduplicate overlapping or duplicate observation windows for the same series unless an explicit derivation proves additivity;
- retain raw platform metric name/value and observation window;
- normalized/derived metrics record transformation/formula version.

Acceptance:
- missing vs zero regression;
- platform-specific metrics do not silently map to false equivalence;
- one content item can be traced from raw metrics to experiment/persona;
- stale windows are marked;
- snapshots 100 then 150 views must not aggregate to 250 views;
- deltas 100 then 50 may aggregate to 150 when semantics declare deltas and windows are non-overlapping/comparable;
- duplicate/overlapping delta windows do not double-count;
- a cumulative snapshot can be converted to a delta only with a valid earlier comparable snapshot and explicit derivation record;
- a supported-but-missing metric retains its expected semantic kind where the platform mapping defines it.

## LEAD-014 finding

Submitted `runtime/metrics.py` preserved missing-vs-zero and platform mappings, but `MetricValue` had no semantic kind and `aggregate_semantic()` summed all PRESENT observations. That directly failed the snapshot-safety contract.

## LEAD-017 repair review

The `915b4b41...` repair is a strong improvement:
- PRESENT metrics now carry semantic kinds;
- cumulative snapshots reduce to latest-per-series instead of summing over time;
- snapshot→delta derivation requires comparable snapshots and records provenance;
- fixtures explicitly prove 100→150 does not become 250.

Two correctness gaps remain before acceptance:

1. **Supported-but-missing metrics lose their known kind.** In `normalize()`, when a platform supports a semantic but the raw metric is absent, the emitted `MetricValue` has `metric_kind=None`. The canonical contract says every normalized metric should retain semantic kind when known. For example, Instagram SAVE is known to be a cumulative snapshot by the platform mapping even when `saved` is missing; losing that kind weakens downstream compatibility checks.

2. **Delta aggregation sums overlapping/duplicate windows blindly.** `aggregate_semantic()` sums every PRESENT `delta` entry without validating non-overlap or duplicate observation windows for the same series. The worker report describes deltas as additive “across windows”; additivity is only safe when windows are compatible/non-overlapping or the data source explicitly defines independent deltas. Add a regression preventing duplicate/overlapping delta double-counting.
