## Goal

Make evidence consumption explicit and lossless across cycles and restarts.

## Current defect

The reviewed implementation can return the whole signal inbox after a fingerprint change and then process only the oldest signal while advancing state past newly arrived evidence.

## Required artifact behavior

- Previously consumed evidence is not reclassified as new.
- A signal added after an earlier completed cycle is processed later.
- Multiple signals arriving before a cycle are not silently lost.
- The semantics for batched evidence are explicit: either process all eligible signals in the bounded unit or persist a cursor/pending set so every signal remains eligible for a later unit.
- Restart does not lose pending evidence.
- No public/external effect.

## Acceptance tests

At minimum:
1. Process signal A; add signal B; next eligible cycle handles B.
2. Add A/B/C before a cycle; prove none disappears from future eligibility.
3. Restart between capture and processing; prove pending evidence remains.
4. Re-running with no new evidence produces deterministic NO_ACTION/no duplicate effect.

- full relevant suite results;
- short explanation of chosen consumption model;
- before/after state example or test fixture;
- known limits.
