# Artifact packet — SB-V15-001

Artifact: Autonomous experiment lifecycle engine
Milestone: V1.5
Lane: Intelligence
Story points: 4
Current status: CHANGES_REQUIRED after LEAD-020 review.

## Goal

Design, register, observe, close and learn from bounded experiments without fabricated measurement or cross-persona private-state leakage.

## Required experiment contract

Each experiment carries:
- bot/runtime identity;
- persona/workspace identity;
- hypothesis;
- baseline measurement references;
- intervention;
- primary metric;
- treatment measurement references;
- observation window;
- stop/safety criteria;
- status lifecycle;
- result/effect-size or honest inconclusive outcome;
- post-experiment learning refs.

## Measurement provenance

Baseline/treatment values must be derived from accepted normalized observations rather than arbitrary caller numeric dictionaries.

Required:
- observation IDs/refs are retained;
- metric semantic, kind and comparable window are validated;
- stale/missing/incompatible observations fail closed or yield INCONCLUSIVE;
- learning/result trace can identify the exact baseline and treatment observations used;
- no fixture/test number may be represented as operational measured performance.

## Persona/workspace isolation

Experiment state is private to the owning bot+persona unless a separate explicit shared/import contract says otherwise.

Normal production APIs must be authoritative bot+persona scoped:
- save/register;
- load/get;
- list/enumerate;
- overlap checks;
- close/update where applicable.

A normal persona-facing caller may not enumerate or load another persona's experiment merely by knowing its experiment ID.

Raw bot-wide access may exist only as an explicitly named/documented admin/internal interface. It must not be the default production read path and must not be used to feed persona-private learning/audience/strategy logic.

## Acceptance

- cannot close before required observation unless stop criterion triggers;
- missing metrics => INCONCLUSIVE, never success;
- duplicate overlapping experiments are detected within the correct bot+persona production scope;
- baseline/treatment require normalized observation provenance and semantic compatibility;
- result/learning refs identify exact measurements used;
- result updates audience/strategy only through evidence refs;
- two personas sharing one bot/runtime may each own experiments without contaminating the other's list/load/overlap behavior;
- persona A production list returns no persona B experiment;
- persona A production load of persona B experiment fails closed/not-found;
- mixed-persona regressions exercise the actual normal production APIs rather than only checking a `persona` field on serialized records;
- any admin/raw bot-wide reader is explicitly separate and cannot be mistaken for the persona production boundary.

## LEAD-020 finding

The latest repair materially closes the original measurement-provenance defect: baseline/treatment bind to normalized observation IDs, compatibility is checked, missing/incompatible data remains INCONCLUSIVE, and learning refs trace exact observations.

Remaining defect: the current persistence/read helpers are still bot-wide (`_dir(bot)`, `load(bot, id)`, `load_all(bot)`) even though each `Experiment` carries a persona. That leaves an easy mixed-workspace production read path.

Required repair before resubmission:
1. add authoritative bot+persona production save/load/list APIs;
2. route normal production experiment lifecycle/read paths through them;
3. keep any raw bot-wide access explicit admin/internal only;
4. add mixed-persona production-path regressions for list/load/overlap isolation;
5. preserve the accepted measurement-provenance behavior.
