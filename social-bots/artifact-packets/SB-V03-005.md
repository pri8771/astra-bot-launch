## Goal

Allow the three runtimes to host their assigned general/cultural personas without concurrent shared-state corruption or accidental persona workspace mixing.

## Current direction

Logical isolation inside shared append-only runtime stores remains an acceptable architecture if production persona-facing reads are structurally persona-scoped and the raw whole-runtime surface is explicitly admin/internal.

Positive progress in `d1e4bee...`:
- `PERSONA_SCOPED_READERS` covers all six persona-scoped stores;
- `persona_records(bot, persona, store)` is a single authoritative facade;
- explicitly named `admin_all_records()` exists for intended whole-runtime audit/admin use;
- generic mixed-persona regressions prove strict filtering and partition coverage through the facade;
- production content dedup already uses persona-scoped content-key reads.

This work is useful and must be preserved.

## Remaining LEAD-024 gap

The facade and documentation alone do not prove every real production read path is constrained by it. The underlying runtime still exposes whole-runtime APIs with ordinary public names, including examples such as:
- `pipeline.publish_queue(bot)`;
- `analytics.events_for(bot)`;
- bot-wide experiment/read helpers and direct append-only readers where applicable.

A normal persona-facing caller can therefore bypass `persona_records()` by convention unless production call sites are actually routed through the persona boundary or the raw APIs are structurally marked/internalized as admin-only.

The artifact requires production-path isolation, not merely a safe helper API and tests of that helper.

## Required properties

- exactly one active mutator for shared runtime state;
- a persona cycle that does not own the runtime fence cannot commit shared state;
- cultural/general concurrent invocations cannot lose counters, evidence-consumption state, hypotheses, or recovery state;
- persona-private/non-shared data has an explicit isolation contract that matches code;
- if physical persona namespaces are claimed, implement and test them;
- if logical isolation inside shared append-only stores is intentionally chosen instead, document the contract and prove every production read/filter path prevents cross-persona contamination;
- no public/external effect.
