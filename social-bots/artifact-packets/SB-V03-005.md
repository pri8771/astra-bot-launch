## Accepted architecture

Logical isolation inside shared append-only runtime stores is accepted because the normal persona-facing boundary is structurally persona-scoped and whole-runtime enumeration is explicitly admin/internal.

Verified implementation properties:
- `RuntimeState` / `PersonaState` separate shared runtime state from persona-private mutable state;
- same captured signal may be considered independently by multiple personas and consumed/hypothesis state remains persona-private;
- `PERSONA_SCOPED_STORES` enumerates all six private store classes: content history, publish queue, experiments, analytics events, action history, decisions;
- `PERSONA_SCOPED_READERS` provides a persona-filtered reader for every one of those stores;
- `persona_records(bot, persona, store)` is the authoritative production dispatcher;
- deliberate whole-runtime enumeration is routed through explicit admin/internal surfaces (`admin_all_records`, `admin_publish_queue`, `admin_events_for`, `admin_content_history` or private admin reader table equivalents);
- the prior ordinary whole-runtime `RuntimeState.content_history()` surface was removed/renamed to an explicit admin surface;
- production dedup and analytics paths remain persona-scoped;
- reconciliation uses explicit admin/runtime-wide access rather than masquerading as persona-facing reads;
- architecture documentation matches the chosen logical-isolation model.
