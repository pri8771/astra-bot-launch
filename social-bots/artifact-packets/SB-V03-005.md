## Goal

Allow the three runtimes to host their assigned general/cultural personas without concurrent shared-state corruption or accidental persona workspace mixing.

## Current architecture

Logical isolation inside shared append-only runtime stores remains acceptable if normal production persona-facing reads are structurally persona-scoped and raw whole-runtime enumeration is explicitly admin/internal.

Positive progress to preserve:
- `RuntimeState` / `PersonaState` separates shared runtime state from persona-private mutable state;
- same shared signal can be independently considered by multiple personas;
- `PERSONA_SCOPED_READERS` covers the six persona-scoped stores;
- `persona_records(bot, persona, store)` is the authoritative scoped facade;
- `admin_all_records()` exists for deliberate whole-runtime admin/reconciliation reads;
- production dedup is persona-scoped;
- analytics aggregation filters persona;
- Core `7e4345b...` routes worker `_reconcile` through the explicit admin boundary;
- `tests/test_production_read_paths.py` exercises mixed real cycles, dedup, aggregate and reconciliation behavior.

## LEAD-025 remaining structural gap

The packet requires raw whole-runtime APIs to be structurally admin/internal or otherwise unavailable as a normal persona-facing interface. The current source still exposes ordinary callable whole-runtime functions, including:
- `pipeline.publish_queue(bot)`;
- `analytics.events_for(bot)`;
- `RuntimeState.content_history()`;
- direct experiment/index/action-history/decision-history enumeration helpers or JSONL reads where applicable.

Comments/docstrings saying “admin” do not enforce the boundary. `isolation.persona_publish_queue()` and `isolation.persona_analytics()` themselves currently filter the results of ordinary raw functions. A normal production caller can therefore still bypass the intended persona facade by convention.

This is now the **only known V03-005 gap**. Do not redesign storage or undo the useful logical-isolation work unless the narrow repair proves insufficient.
