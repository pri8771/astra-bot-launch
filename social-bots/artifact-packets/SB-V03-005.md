## Goal

Allow the three runtimes to host their assigned general/cultural personas without concurrent shared-state corruption or accidental persona workspace mixing.

## Current direction

Serializing mutations at the runtime boundary (`cycle:<bot>`) is directionally correct because `bot_state.json` is shared by personas hosted on one runtime.

However, this artifact is not accepted until the active-cycle fence in `SB-V03-004` is correct. A lease that can expire while its old owner continues committing does not provide reliable runtime serialization.

The current architecture documentation also states that persona non-shared experiment/content/memory data is isolated in nested namespaces, while current `paths.py` accepts bot namespaces only and decision/pipeline storage is bot-scoped. Reconcile that mismatch.

## Required properties

- exactly one active mutator for shared runtime state;
- a persona cycle that does not own the runtime fence cannot commit shared state;
- cultural/general concurrent invocations cannot lose counters, evidence-consumption state, hypotheses, or recovery state;
- persona-private/non-shared data has an explicit isolation contract that matches code;
- if physical persona namespaces are claimed, implement and test them;
- if logical isolation inside shared append-only stores is intentionally chosen instead, document the contract and prove every read/filter path prevents cross-persona contamination;
- no public/external effect.

## Acceptance tests

1. General + cultural persona race on one runtime: only the fenced owner mutates shared runtime state.
2. Force lease loss/takeover during a running persona cycle: the old owner cannot commit afterward.
3. Prove no duplicate signal consumption and no lost cycle/hypothesis update.
4. Prove non-shared persona history/experiments/content cannot be mistaken for another persona's data under the chosen isolation model.
5. Architecture documentation and path implementation agree.
