## Goal

Restore an earlier accepted strategy version when rollback criteria are met, with full receipt lineage. This slice only decides *whether* and *when* to call SB-S20-006's `rollback_to`; it introduces no new persistence format of its own.

## Interfaces

`evaluate_rollback_condition(state, evidence, now) -> bool | None` (`None` = cannot evaluate → no rollback); `execute(bot, persona, *, evidence, fence=None)` (calls SB-S20-006's `strategy.rollback_to`, then writes a receipt via `runtime.receipts.write_receipt`).

## Deterministic vs model responsibility

Pure comparison of `state.revision["rollback_condition"]` (`metric`/`direction`/`threshold`/`window_hours`) against resolved evidence; no provider. `execute` only calls existing deterministic functions (`rollback_to`, `write_receipt`).

## Fail-closed behavior

- Condition's metric unresolvable in `evidence` → `evaluate_rollback_condition` returns `None`; `execute` HOLDs (no rollback, no receipt claiming a rollback happened).
- Condition evaluates `False` → no rollback, no state change.
- `execute` called with a lost fence → `FenceLost`, target strategy version untouched, no receipt.

## Tests (focused + adversarial)

1. condition met (metric below threshold within window) → `execute` calls `rollback_to`, produces a receipt referencing the restored version.
2. condition not met → no rollback, no receipt claiming a rollback.
3. metric unresolvable → `evaluate_rollback_condition` returns `None`; `execute` HOLDs, does not roll back.
4. `window_hours` boundary: evidence just outside the window excluded, just inside included.
5. fence-loss during `execute` → `FenceLost`, zero durable writes, no receipt.
6. receipt lineage: the receipt's `evidence_refs` match exactly the refs that satisfied the condition — no extras, no omissions.
7. persona-scope: evaluating/executing rollback for persona A never reads persona B's evidence or state.
8. calling `execute` twice on an already-rolled-back state is a no-op on the second call (mirrors SB-S20-006's "rollback to already-active version" rejection).
