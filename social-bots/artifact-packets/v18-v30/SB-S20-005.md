## Goal

Rank opportunities by expected growth, expected learning, confidence, risk and opportunity cost under hard budgets. Ranking is pure arithmetic over already-validated opportunities; it never re-validates opportunity shape and never persists anything.

## Interfaces

`BudgetView` protocol (`remaining(kind) -> int | None`); `StaticBudgetView`; `ScoreWeights`; `score(batch, *, budget: BudgetView, weights: ScoreWeights) -> list[ScoredOpportunity]`. `batch` is an `OpportunityBatch.accepted` list (SB-S20-002 output).

## Deterministic vs model responsibility

Entirely deterministic weighted arithmetic (expected growth, expected learning, confidence, minus a risk/opportunity-cost term). No provider and no proposer seam exists in this module at all.

## Fail-closed behavior

- Non-finite score inputs → that opportunity is excluded from ranking, never scored as `0`.
- `budget.remaining(kind) == 0` → every opportunity of that kind excluded from the ranked list.
- `remaining(kind)` returning `None` for an untracked kind never blocks scoring for that kind (documented as "not tracked", never coerced to `0`).
- Unknown `ScoreWeights` field → rejected at construction.
- Empty batch → empty ranked list, never an exception.

## Tests (focused + adversarial)

1. basic ranking order matches a hand-computed weighted score on three fixture opportunities.
2. opportunity with missing `confidence` excluded from ranking, not scored as `0` (missing≠zero), and reported separately rather than silently dropped.
3. a single opportunity with an extreme `expected_growth_value` but only one supporting evidence ref does not dominate the ranked list once a companion low-confidence flag is present, mirroring the strategy track's "single anomalous observation" bound at scoring time.
4. `StaticBudgetView.remaining("model_calls") == 0` → every model-call-costed opportunity excluded, non-model opportunities unaffected.
5. `remaining()` returning `None` for an untracked budget kind never blocks scoring for that kind.
6. non-finite (`NaN`/`inf`) input on any scored field excludes that opportunity, no exception raised.
7. persona-scope: scoring one persona's batch never reads or is influenced by another persona's `BudgetView`.
8. empty batch → `[]`.
9. `ScoreWeights` with an unknown field rejected at construction.
10. the tie-break rule (declared once, tested here) is deterministic and stable across repeated calls on the same input.
