## Interfaces

```
verify(result: WorkerResult, contract: WorkerContract, sandbox: Sandbox) -> list[str]
    # validate_result (S23-001) + every output path exists in scratch + sha256 matches + declared schema matches
    # the file's "schema" field + for ReviewResult: reviewed_sha256 still matches the reviewed inputs
adopt(result, contract, *, bot, persona, fence=None, keep: list[str] | None = None) -> AdoptionReceipt
    # precondition: verify() == []; copies kept outputs via sandbox.retire(keep=...) into
    # receipts_dir(bot)/specialists/<worker_id>/, writes receipts.write_receipt(namespace=bot, kind="specialist", ...)
    # inside fence.fenced_commit when fence is given; returns receipt with adopted paths + hashes
reject(result, contract, sandbox, reasons: list[str]) -> RejectionReceipt
    # writes receipts.write_receipt(kind="specialist", status="REJECTED", reasons) then sandbox.retire(keep=[])
integrate_into(kind: str, adopted: AdoptionReceipt) -> dict
    # deterministic mapping table: "ResearchResult/1" -> evidence refs list; "DraftResult/1" -> candidate draft dict
    # (status DRAFT_UNPUBLISHED preserved); "AnalysisResult/1"/"ReviewResult/1" -> attached to the receipt only.
    # It RETURNS a value for the parent to use; it never writes PersonaState/RuntimeState/content/experiments.
```
`AdoptionReceipt` and `RejectionReceipt` carry `worker_id`, `parent_run_id`, `bot`, `persona`, `role`, `decision`, `reasons`, `outputs[{path, sha256}]`, `at`, `schema_version`.

## Deterministic vs model responsibility

Entirely deterministic. The parent's later use of an adopted draft still passes through the existing reasoning/policy gates (`decision`), which are not part of this slice.

## Fail-closed behavior

- `adopt` with non-empty `verify()` errors → `IntegrationError`, no receipt, scratch untouched (caller must call `reject`).
- Hash mismatch between `WorkerResult.outputs` and the file on disk → error (a specialist cannot swap content after declaring it).
- Fence lost during `adopt` → `FenceLost`; no receipt, no copied files (copy happens inside the fenced closure; retire only after commit succeeds).
- `integrate_into` for an unknown schema → error; a `DraftResult` whose `status != "DRAFT_UNPUBLISHED"` → error.
- Parent state files (`state/<bot>/*`, `content/`, `experiments/`) are byte-identical before/after both `adopt` and `reject` (tests snapshot them).

## Tests (focused + adversarial)

1. Happy path: research result → `verify()==[]` → `adopt` → receipt, files under `receipts/<bot>/specialists/<worker_id>/`, scratch gone.
2. Tampered output after declaration → `verify` error → `adopt` raises.
3. Output path outside scratch in `WorkerResult` → `verify` error.
4. `effect_attempts=1` → `verify` error → `reject` writes REJECTED receipt; parent state snapshot identical.
5. Reviewer result whose `reviewed_sha256` no longer matches inputs → `verify` error.
6. Fence-loss during `adopt` → nothing written, scratch still present (so caller can `reject`).
7. `integrate_into("DraftResult/1")` returns the candidate with `status` preserved; a result carrying `status="QUEUED"` → error.
8. Persona scope: adopt with `persona` different from `contract.persona` → error before any write.
9. `reject` then `adopt` on the same worker → error (retired).
10. Parent state snapshot (all of `state/`, `content/`, `experiments/`, `memory/`) identical across every test.
11. Two workers adopted concurrently for different personas → both receipts, no cross-contamination of receipt dirs.
