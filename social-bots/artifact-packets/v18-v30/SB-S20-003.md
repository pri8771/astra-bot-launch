## Goal

## Interfaces

`ChangeOp(op, target, value, evidence_refs)`; `StrategyRevisionProposal(...)` exactly per spec §2.2; `validate_proposal(p, current: StrategyState) -> list[str]`; `propose(current, batch: OpportunityBatch, *, evidence, proposer: Proposer | None = None) -> StrategyRevisionProposal`. `proposer` defaults to `None` (deterministic template); any real proposer resolves only through `runtime.live_route_guard.check`.

## Deterministic vs model responsibility

`propose()` is deterministic by default: it maps accepted opportunity types onto typed `ChangeOp`s. An optional proposer may suggest additional changes, but every suggestion still passes through `validate_proposal` before inclusion; policy authority (S20-004) is untouched here.

## Fail-closed behavior

- Unknown `op` → rejected.
- Missing `target` → rejected.
- Non-finite `value` → rejected.
- Weight `value` outside `[0,1]` → rejected.
- `required_authority` other than `"none"` → rejected.
- `current_version` mismatch against `current.version` → rejected.
- Empty `evidence_refs` on any op other than `NO_CHANGE`/`REQUEST_MORE_EVIDENCE` → rejected.
- Any dict-merge payload (a key not defined on `ChangeOp`/the dataclass) → rejected.

## Tests (focused + adversarial)

1. accepted `OpportunityBatch` → proposal with typed `ChangeOp`s referencing the batch's evidence refs.
2. raw dict merge (extra key on a `ChangeOp`) rejected.
3. `required_authority="public_post"` injected into a proposal rejected.
4. op targeting a weight `value` outside `[0,1]` rejected.
5. empty `evidence_refs` on `SET_PLATFORM_WEIGHT` rejected; `NO_CHANGE` with empty `evidence_refs` accepted.
6. `current_version` mismatch (stale `current`) rejected.
7. unresolvable/missing evidence ref in the batch → the op is omitted, proposal falls back to `NO_CHANGE`/`REQUEST_MORE_EVIDENCE`, never fabricated.
8. persona-scope: a batch for persona B cannot produce a proposal against persona A's `current_strategy_id`.
9. `proposer=None` and a fixture-proposer path both produce a valid proposal; suggestions that fail `validate_proposal` are dropped, not raised to the caller.
10. missing `confidence` in the batch stays `None` on the proposal (missing≠zero).
11. empty `OpportunityBatch` → `NO_CHANGE` proposal, no exception.
12. `reversibility`/`rollback_condition` are always populated (never `None`) on any non-`NO_CHANGE` proposal.
