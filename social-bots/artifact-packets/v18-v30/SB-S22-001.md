## Goal

Represent high-level goals with measurable success criteria, time horizon, authority, budgets and stop conditions. A `Goal` is authored data, not derived state; this slice only defines and persists the schema.

## Interfaces

`Goal(goal_id, bot, persona, objective, success_metric, evidence_baseline_refs, time_horizon, allowed_authority, budgets, stop_conditions, status, created_at)` per spec §2.5; `validate_goal(g) -> list[str]`; `save_goal(g, *, fence=None)`; `load_goal(bot, persona, goal_id)`; `list_goals(bot, persona)`.

## Deterministic vs model responsibility

Entirely deterministic. A `Goal` is authored by the lead/owner or a deterministic template; it is never proposed by a model in this slice.

## Fail-closed behavior

- `allowed_authority` containing anything outside `{"create_candidate","register_experiment","update_state"}` → refuse.
- `budgets.external_effects != 0` → refuse.
- `success_metric.direction` not in `{"up","down"}` → refuse.
- `time_horizon.end <= time_horizon.start` → refuse.
- Unsafe `bot`/`persona` → `ValueError`, nothing written.

## Tests (focused + adversarial)

1. valid `Goal` saves and round-trips through `load_goal` byte-for-byte.
2. `allowed_authority` containing `"public_post"` rejected.
3. `budgets.external_effects=1` rejected.
4. `success_metric.direction="sideways"` rejected.
5. `time_horizon.end` before `time_horizon.start` rejected.

9. duplicate `goal_id` write refused (mirrors SB-S20-001's version-exists guard).
10. `evidence_baseline_refs` containing a bare number/string (not a dict) rejected.
