## Goal

Prove strategy revisions are reversible and contradictory evidence cannot silently overwrite history. Rollback restores a prior version's content as a brand-new version; it never edits a version file that already exists.

This slice extends `runtime/strategy.py` (owned by SB-S20-001) with `rollback_to(bot, persona, version, *, reason, evidence_refs, fence=None)`, per the spec's own module map (§3, S20-006 row lists no separate module). No other file under `runtime/` is touched; `decision.py`, `state.py` and `paths.py` remain untouched.

## Interfaces

`rollback_to(bot, persona, version, *, reason, evidence_refs, fence=None) -> StrategyState`. Creates version `N+1` whose content equals the target version's fields, with `revision={"restores_version": target, "reason":..., "evidence_refs":...}`; never edits the target version file.

## Deterministic vs model responsibility

Entirely deterministic. No provider. `reason`/`evidence_refs` are caller-supplied typed data, not model output.

## Fail-closed behavior

- Target version does not exist → refuse, nothing written.
- Target version already equals the active version → refuse (a no-op rollback is rejected, not silently accepted).
- Empty `evidence_refs` → refuse.
- Fence lost → `leasing.FenceLost`, no partial files (version → HISTORY → HEAD in one `fenced_commit`, matching SB-S20-001's pattern).

## Tests (focused + adversarial)

1. rollback from v3 to v1 creates v4 with v1's content and `revision.restores_version=1`; v1 bytes unchanged.
2. rollback to the currently active version rejected.
3. rollback to a nonexistent version rejected, nothing written.
4. rollback with empty `evidence_refs` rejected.
5. an attempt to rewrite v1 directly (bypassing `rollback_to`) is detected by `history()`'s hash check (mirrors SB-S20-001's tamper test), proving rollback is the only reversal path.
6. fence-loss during rollback → `FenceLost`, zero durable writes.
7. two personas: rollback on persona A never touches persona B's HEAD/HISTORY.
8. `HISTORY.jsonl` gets the rollback event and the `supersedes` chain stays unbroken (points at the version rolled back *from*, not the restored version).
