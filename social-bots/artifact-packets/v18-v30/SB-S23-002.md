## Goal

Isolate temporary worker scratch state, inputs, outputs and cleanup from persistent persona/brand stores. A specialist can only read what was materialized into its scratch dir and can only write inside it; retirement removes everything except explicitly kept, attributable evidence.

## Fail-closed behavior

- Any containment violation raises `SandboxEscape` before any filesystem call; tests assert no file/dir is created outside scratch (compare directory snapshots of `SBOTS_HOME`).
- `retire` on an already-retired sandbox → no-op returning the recorded status; `keep` entries that fail containment → `FAILED` with nothing copied.
- `materialize_context` with a resolver error → the sandbox is left with a `context/FAILED.json` note and the specialist must not run (S23-008 checks this).
- `PersonaSnapshotResolver` never exposes `PersonaState`/`RuntimeState` objects, `state_dir` paths, or `admin_*` readers.

## Tests (focused + adversarial)

1. create → write `out/result.json` → read → list; dir mode 0o700.
2. `write("../x")`, `write("/etc/x")`, `write("a/../../x")` → `SandboxEscape`; snapshot of `SBOTS_HOME` unchanged.
3. Symlink inside scratch pointing outside → `write`/`read` through it refused.
4. `materialize_context` with `DictContextResolver` → files + sha256 refs; returned objects are dicts, not the resolver's live objects (mutating the return value does not mutate resolver data).
5. `PersonaSnapshotResolver` for persona A: ref to persona B → `ScopeError`; ref to A → snapshot.
6. `retire(keep=["out/result.json"])` → file present under receipts dir with sha256 index, scratch dir gone; second retire → same status, no error.
7. `retire(keep=["../escape"])` → `FAILED`, receipts dir has nothing new.
8. Two sandboxes (personas A and B, same bot) cannot `read` each other's paths even with the other's worker_id in `relpath`.
9. `create` twice for the same contract → `SandboxError`.
10. Invalid contract (from S23-001 errors) → `Sandbox.__init__` raises, nothing created.
