## Interfaces

`CooldownConfig`; `check(history, proposal, now) -> (ok: bool, reasons)`. `history` is the list read via `strategy.history(bot, persona)`.

## Deterministic vs model responsibility

Pure lookback over `history` timestamps and event types. No provider.

## Fail-closed behavior

- No prior `ACCEPTED` revision in `history` → `ok=True` (nothing to cool down from).
- Malformed/unsorted `history` entries are ignored for cooldown purposes rather than raising, but noted in `reasons` when any were skipped.
- A proposal arriving inside the cooldown window → `ok=False` with the remaining-cooldown reason, never silently shortened.

## Tests (focused + adversarial)

1. proposal one hour after an `ACCEPTED` revision inside a 72h cooldown → `ok=False`.
2. proposal 73 hours after → `ok=True`.
3. empty history → `ok=True`.
4. history containing only `REJECTED`/`HOLD` events (no `ACCEPTED`) → `ok=True` regardless of timing.
5. `CooldownConfig(cooldown_hours=0)` → always `ok=True` (an explicit opt-out is representable, not a silent bypass of some other check).
6. the same call signature as SB-S20-004's interim cooldown check is exercised by re-running SB-S20-004's cooldown test against this module directly with identical inputs/outputs.
7. persona-scope: cooldown computed from persona A's history never considers persona B's history rows.
8. a malformed history row (missing `at`) is skipped and reported in `reasons`, not fatal.
