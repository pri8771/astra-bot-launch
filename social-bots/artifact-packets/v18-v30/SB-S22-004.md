## Goal

Reject cyclic, impossible, authority-violating or unbounded decompositions. This is the single gate every `PlanDAG` must pass before it is treated as active, whether freshly generated or replanned.

## Interfaces

`validate_plan(dag, constraints, limits) -> list[str]` (cycle via Kahn's algorithm, authority check against `constraints`, unbounded check, missing `completion_test`, duplicate `task_id`, dangling edge, depth check against `limits.max_depth`).

## Deterministic vs model responsibility

Pure graph validation. No provider.

## Fail-closed behavior

- Any single violation → non-empty error list; the DAG is never partially accepted.
- A cycle detected by Kahn's algorithm (nodes remaining after topological sort) → error naming the cycle.
- A task's `required_authority` not a subset of `constraints`'s allowed set → error.
- `budget.external_effects>0` anywhere → error.
- Task count `> limits.max_tasks` or a task's `depth > limits.max_depth` → error.
- An edge referencing a nonexistent `task_id` → error.

## Tests (focused + adversarial)

1. valid acyclic DAG within limits → `[]`.
2. two-node cycle detected via Kahn's algorithm, named in the error.
3. task `required_authority` exceeding `constraints`'s allowed set → error.
4. `external_effects>0` on any task → error.
5. task count one over `limits.max_tasks` → error.
6. a task's `depth` one over `limits.max_depth` → error.
7. two differently-worded tasks sharing the same `task_id` (dedup collision, not a true duplicate submission) → error naming both.
8. an edge referencing a `task_id` not present in `tasks` (dangling edge) → error.
9. a task missing `completion_test` → error.
10. blocked-platform goal: a DAG containing only read-only preparatory tasks for the blocked platform validates clean; a DAG with a writing task for that platform fails authority/availability validation.
11. persona-scope: validating a DAG never reads another persona's plans/constraints.
12. a DAG with zero tasks (fully covered goal) validates clean and returns `[]`.
