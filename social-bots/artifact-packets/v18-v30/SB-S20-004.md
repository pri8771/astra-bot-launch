## Goal

Enforce evidence floors, confidence floors, max change magnitude, cooldown, route availability and zero-spend / zero-public-authority constraints on every `StrategyRevisionProposal`, then persist accepted revisions as new immutable versions.

## Interfaces

```
PolicyConfig(min_evidence_count=2, min_confidence=0.5, max_weight_delta=0.15, max_ops_per_revision=3,
             cooldown_hours=72, max_evidence_age_hours=336, allowed_platforms=None)
validate(proposal, current, *, evidence: EvidenceIndex, availability: dict, config, now=None) -> PolicyVerdict
apply(current, proposal, verdict) -> StrategyState            # pure; verdict must be ACCEPT
commit_revision(current, proposal, verdict, *, fence=None) -> StrategyState
```
`EvidenceIndex` protocol: `resolve(ref) -> dict | None`, `age_hours(ref, now) -> float | None`. Ship `DictEvidenceIndex` for tests.  
`availability` is the same `{platform: {"available": bool, "reason": str}}` dict `growth_evaluator.evaluate` consumes.

Verdict order (first failure wins, all reasons still collected): schema (`validate_proposal`) → version match → `required_authority == "none"` → op count → per-op bounds (weight delta ≤ `max_weight_delta`, resulting weights normalize to 1.0, no negatives) → platform availability for any `SET_PLATFORM_WEIGHT` increase → evidence floor (resolvable, non-fixture-in-operational-mode, count ≥ floor, none older than `max_evidence_age_hours`) → confidence floor → cooldown. `NO_CHANGE`/`REQUEST_MORE_EVIDENCE` proposals are always ACCEPT-able with no state change and no new version.

## Deterministic vs model responsibility

100% deterministic. The proposer (S20-003, possibly model-backed later) never influences the verdict except through the typed proposal content. There is no override flag.

## Fail-closed behavior

- Any reason → `REJECT` or `REQUEST_MORE_EVIDENCE`; `apply` raises if called with a non-ACCEPT verdict.
- Unresolvable evidence ref = missing = does not count (never zero, never a pass).
- Missing `availability` entry for a platform = unavailable.
- `commit_revision` writes version → HISTORY → HEAD inside one fenced commit when `fence` is given; a REJECT persists only a HISTORY row `{event: "REJECTED", verdict_id, reasons}`.

## Tests (focused + adversarial)

1. Accept: 2 fresh resolvable refs, confidence 0.7, delta 0.10 → new version, weights renormalized, HISTORY has PROPOSED+ACCEPTED rows.
2. Reject: delta 0.30 > max.
3. Reject: `required_authority="public_post"`.
4. Reject: increase weight on unavailable platform.
5. REQUEST_MORE_EVIDENCE: one ref only; one ref unresolvable; one ref older than max age.
6. Reject: single anomalous observation (one ref with `samples=1` and extreme value) cannot pass floor of 2.
7. Cooldown: second proposal 1h after an accepted one → REJECT with cooldown reason; 73h later → ACCEPT.
8. `NO_CHANGE` proposal → ACCEPT, `active()` version unchanged, HISTORY row added.
9. Fixture refs under operational mode (`evidence.operational=True`) → REQUEST_MORE_EVIDENCE.
10. Fence-loss: `commit_revision` with lost fence → `FenceLost`, no files.
11. Version mismatch (`current_version` stale) → REJECT.
12. Persona scope: proposal for persona B against persona A's state → REJECT.
