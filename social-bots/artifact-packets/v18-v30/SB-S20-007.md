## Interfaces

Bundle: `manifest.json` (source SHA, command, mode, sha256 of every input/output, `classification: "fixture"|"live"`), `strategy_before.json`, `proposal.json`, `verdict.json`, `strategy_after.json`, `history.jsonl`, and for the second run `rollback_or_hold.json`.

## Deterministic vs model responsibility

Deterministic end to end. A model proposer is optional and, if used, needs its own manifest through `live_route_guard`; the acceptance claim rests only on the deterministic verdict chain.

## Fail-closed behavior

- `--mode live` refuses any input with `provenance in {"fixture","test-only"}` and exits non-zero with the offending refs listed; the bundle then carries `classification: "refused"`.
- `--mode rehearsal` labels everything `fixture` and writes `LIVE: false` in the manifest header; the test asserts a rehearsal bundle cannot be mistaken for live (manifest schema requires `classification`).
- No evidence → NO_CHANGE bundle; the runner never fabricates a change to satisfy the artifact.
- Rollback is only executed when `evaluate_rollback_condition` returns `True`; `None` (cannot evaluate) → HOLD with reason.

## Tests (focused + adversarial)

Engineering test file exercises the runner in rehearsal mode on fixtures: (1) positive evidence → bounded ACCEPT; (2) contrary later evidence → rollback version; (3) missing data → NO_CHANGE/REQUEST_MORE_EVIDENCE; (4) `--mode live` on fixtures → refusal; (5) manifest hashes verify. These mirror `V2_ENGINEERING_ACCEPTANCE.md` scenarios A–E; scenarios F–G belong to S20-002/S20-004 tests.

## Evidence to return

- Rehearsal: bundle path + test output, labeled ENGINEERING.
- LIVE: bundle from real observations with account alias (no credentials), window, exact source SHA, and independent Acceptance re-execution of the verdict chain on the same inputs.

## Owner / lead gates

- Owner: authorization of the analytics/account read used for the live inputs (no public effect is needed for this artifact).
- Lead: manifest presence check, independent Acceptance execution, then `ACCEPTED` on LIVE evidence only. A rehearsal-only submission can be accepted **as engineering evidence for V2.0 engineering-readiness (SB-V20-099)**, never as operational V2.0.
