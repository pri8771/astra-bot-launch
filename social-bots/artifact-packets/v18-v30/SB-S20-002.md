## Goal

Consume analytics/audience/experiment evidence as typed GrowthOpportunity records without granting action authority. Intake classifies and validates records already produced by Intelligence; it never derives new numbers and never touches strategy state.

## Interfaces

Input: the `dict` form emitted by `growth_evaluator.evaluate()` (`ranked[*]`, `blocked[*]`), validated against CROSS_LANE §7 (`GrowthOpportunity`).
Output: `validate_opportunity(d) -> list[str]`; `intake(batch: list[dict], *, bot, persona, require_evidence: bool) -> OpportunityBatch(accepted: list[dict], rejected: list[{"index","reasons"}])`.

## Deterministic vs model responsibility

Entirely deterministic. Intake never invokes a provider and never mutates strategy; it only validates and partitions records that Intelligence already produced.

## Fail-closed behavior

- Scope mismatch (`bot`/`persona` on the item vs. the call) → rejected.
- `required_authority` other than `"none"` → rejected.
- `cost_class` other than `"no_spend"` → rejected.
- `provenance="test-only"` under `require_evidence=True` → rejected.
- Non-finite numerics or unknown keys → rejected.
- A batch is never partially adopted into strategy; intake only returns accepted/rejected lists for the caller.

## Tests (focused + adversarial)

1. valid ranked opportunity accepted.
2. `required_authority="public_post"` rejected.
3. `cost_class="paid_promotion"` rejected.
4. `provenance="test-only"` + `require_evidence=True` rejected; same record with `require_evidence=False` accepted (labeled fixture).
5. bot/persona scope mismatch between a batch item and `intake()`'s own arguments rejected.
6. non-finite `expected_growth_value` (NaN/inf) rejected.
7. unknown key on an opportunity dict rejected — no silent passthrough.
8. missing `confidence` field stays `None` on the accepted record, never coerced to `0.0` (missing≠zero), and never used to rank.
9. two personas' batches processed independently in one call; accepted/rejected counts never leak across persona.
10. `blocked[*]` entries with a reason are surfaced as rejected with the original reason preserved, not re-derived.
11. empty batch → `OpportunityBatch(accepted=[], rejected=[])`, no exception.
12. malformed batch item (missing `opportunity_id`) rejected before any other field is read.
