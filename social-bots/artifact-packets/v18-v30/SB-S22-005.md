## Goal

Replan only unfinished work when evidence or blockers change, preserving completed artifacts and history. `DONE` tasks are never regenerated or altered; the replanned DAG still has to pass SB-S22-004's validator before it is returned.

## Interfaces

`replan(previous: PlanDAG, goal, *, changed_evidence, blockers, ...) -> PlanDAG`. `DONE` tasks are copied by `task_id`, unchanged (byte-identical content and hash); only unfinished (`PLANNED`/`READY`/`RUNNING`/`BLOCKED`) tasks are regenerated; the result is `version+1` with `supersedes=previous.version`; it still passes `plan_validator.validate_plan` before being returned.

## Deterministic vs model responsibility

Deterministic regeneration using the same template logic as SB-S22-002's `plan`, seeded by `changed_evidence`/`blockers` instead of a fresh opportunity batch; no provider beyond the same optional proposer seam SB-S22-002 exposes.

## Fail-closed behavior

- Any `DONE` task whose regenerated content would differ is a bug, not a feature — the test suite asserts byte-identical `DONE` task content/hash across replans.
- A new blocker on a platform → only read-only preparatory tasks survive/are regenerated for that platform; no writing task is silently re-added.
- `replan` never edits `previous`'s stored version file (immutable, same as strategy versions).
- A replan that produces an invalid DAG (fails `validate_plan`) is refused, not persisted.

## Tests (focused + adversarial)

1. `DONE` tasks copied byte-identical (content and hash) across a replan.
2. only `PLANNED`/`READY`/`RUNNING`/`BLOCKED` tasks regenerated; `CANCELLED` tasks stay `CANCELLED`, not resurrected.
3. a new blocker on a platform → regenerated tasks for that platform are read-only preparatory kinds only.
4. `changed_evidence` invalidating a prior `RESEARCH` task's premise regenerates its downstream chain but leaves any already-`DONE` `MEASUREMENT` task untouched.
5. resulting `PlanDAG.version == previous.version + 1` and `supersedes == previous.version`.
6. `previous`'s stored version file is byte-unchanged after `replan` runs.
7. a replan that would produce a cyclic or over-limit DAG is refused (delegates to `plan_validator.validate_plan`); the previous plan remains active.
8. persona-scope: replanning persona A's plan never reads or writes persona B's plans.
9. replanning with no `changed_evidence` and no `blockers` is a no-op (returns an equivalent DAG or explicitly declines, never manufactures busywork).
