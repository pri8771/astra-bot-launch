## Goal

Decompose a goal into artifact-addressable tasks with dependencies and explicit completion tests. Decomposition is deterministic and template-driven; an optional proposer may only suggest additional tasks subject to the same downstream checks.

## Interfaces

`PlannedTask`, `PlanDAG` per spec §2.5; `plan(goal, *, strategy: StrategyState | None, opportunities: OpportunityBatch | None, constraints: PlannerConstraints, limits: PlannerLimits, proposer=None) -> PlanDAG | NoNewWork`; `save_plan`; `active_plan`. For each accepted opportunity/hypothesis the deterministic template emits `RESEARCH → EXPERIMENT_DESIGN → CONTENT_CANDIDATE → MEASUREMENT → REVIEW` (only the kinds the authority allows); `task_id = sha256(goal_id|kind|key)[:16]`, deterministic and dedup-able; an optional `proposer` may suggest extra `PlannedTask`s which pass through the same validation as the template's own output, and a rejected suggestion is logged, never executed; `NoNewWork(reason)` is returned when the goal is already fully covered.

## Deterministic vs model responsibility

Template-driven and deterministic by default. A proposer is optional, must be constructed through `runtime.live_route_guard.check` if it is anything other than the deterministic default, and its suggestions carry no extra authority — they are just more candidate `PlannedTask`s subject to the same checks as the template's own output.

## Fail-closed behavior

- Goal `allowed_authority` missing a kind → that stage of the chain is omitted entirely, not degraded or faked.
- Two opportunities with the same dedup key produce the same `task_id` (never two tasks for one key).
- A limits breach at generation time (e.g. would exceed `max_tasks`) → `plan` stops emitting further tasks and returns the truncated DAG plus a note; it does not silently exceed the limit and rely on SB-S22-006 to catch it later.
- A proposer suggestion missing `completion_test` → dropped, logged, never included.

## Tests (focused + adversarial)

1. one accepted opportunity → full `RESEARCH→...→REVIEW` chain with correct `depends_on` edges.
2. authority missing `"register_experiment"` → chain omits `EXPERIMENT_DESIGN`, later stages depend directly on `RESEARCH`.
3. two same-key opportunities (differently worded) → identical `task_id`, single task, not duplicated.
4. `NoNewWork` returned when every opportunity already has a non-`CANCELLED` task in the previous plan.
5. `external_effects>0` anywhere in a goal's budgets is rejected before any task is generated.
6. proposer suggestion missing `completion_test` dropped and logged, not raised to the caller.
7. generation stops at `limits.max_tasks` and returns a truncated DAG with a note, never silently over-generates.
8. `strategy=None` and `opportunities=None` both handled (goal-only planning) without exception.
9. persona-scope: planning for persona A never reads persona B's goals/plans/strategy.
10. missing `expected_evidence`/optional fields stay `[]`/`None`, never fabricated.
11. `planner_limits.PlannerLimits()` defaults are actually applied (not bypassed) even though `enforce()` does not exist yet in this slice.
