## Fail-closed behavior

- Any input not labeled `provenance="fixture"` is refused.
- A scenario that fails `validate_plan`/`enforce` is recorded in the bundle as a failure, not silently retried into a passing shape.
- `manifest.json` always carries `classification: "fixture"`.

## Tests (focused + adversarial)

1. fixture goal → valid `PlanDAG` produced, passes `validate_plan` and `enforce` with `[]` errors.
2. cyclic-DAG fixture (constructed adversarially) → runner reports the `validate_plan` errors, does not proceed to "execute".
3. authority-exceeding task fixture → rejected by `validate_plan`, bundle records why.
4. `external_effects>0` fixture task → rejected by `enforce`, independent of configured limits.
5. seeded blocker on a platform → `replanner.replan` output contains only read-only preparatory tasks for that platform.
6. `DONE` tasks from the "safe subset execution" step are byte-identical in `dag_v2_replanned.json` vs. `dag_v1.json`.
7. `> max_tasks` fixture → `enforce` error, runner does not truncate and re-attempt silently.
8. manifest hash verification: re-hashing every listed bundle file matches `manifest.json`.
9. persona-scope scenario: two personas run through one invocation, plans/DAGs never cross.
