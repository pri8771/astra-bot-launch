Inputs are read only from `scratch/context/*` and `scratch/inputs/*` (materialized by the parent, S23-006/S23-008); outputs go to `scratch/outputs/<role>_result.json`. The reviewer records sha256 of every file it reviewed; the parent (S23-006) uses this to prove the reviewer changed nothing.

## Deterministic vs model responsibility

Deterministic default analyst: findings = one per evidence ref with `confidence=None` (unknown, not zero). Deterministic default reviewer: schema/ref-integrity review (every finding cites a resolvable evidence file in scratch; every claim in a draft has a finding). Optional provider (wrapped by S23-007) may add findings/issues, but a finding without evidence refs is moved to `unsupported_claims`, never kept as a finding, and a provider cannot flip a `FAIL` caused by deterministic integrity checks to `PASS`.

## Fail-closed behavior

- Role mismatch → `RoleMismatch`.
- Reviewer has no `write` access outside its own result file: `sandbox.write` calls for any other path raise and the run returns `FAILED`.
- Any input file missing/unreadable → `NEEDS_EVIDENCE` (reviewer) / `limitations` (analyst); never assumed PASS.
- Deadline → `TIMED_OUT`.
- `effect_attempts` always 0 by construction.

## Tests (focused + adversarial)

1. Analyst over a `ResearchResult/1` with 3 refs → 3 findings, each citing a ref, `confidence=None`.
2. Provider-supplied finding with no refs → lands in `unsupported_claims`.
3. Reviewer PASS on a consistent draft+findings bundle; `reviewed_sha256` matches actual files.
4. Reviewer FAIL when a draft claim has no finding; provider says PASS → still FAIL (deterministic veto).
5. Reviewer attempting to write `inputs/draft.json` → run returns `FAILED`; file bytes unchanged.
6. Missing input → `NEEDS_EVIDENCE`.
7. Role mismatch for both classes.
8. Persona scope: inputs materialized for persona A; contract persona B → refused at sandbox level (S23-002) → `FAILED` with error.
9. Deadline 0s → `TIMED_OUT`.
10. Module source contains none of: `pipeline`, `decision`, `content_dir`, `publish`, `enqueue`, `PersonaState`.
