## Goal

Compile owner/public/spend/model/account limits into planner constraints before task generation. Compilation can only narrow what a `Goal` already declared; it can never widen it.

## Dependencies

Engineering: requires the listed slice present on the implementation branch as a new file.

## Interfaces

`PlannerConstraints`; `compile(*, authority: decision.Authority, availability: dict, live_authorized: bool, budgets: dict) -> PlannerConstraints`. Reads `decision.Authority` (`can_public_post=False, can_spend=False, can_message_users=False` in the loop) read-only; never constructs or mutates an `Authority`.

## Deterministic vs model responsibility

Pure compilation of already-deterministic inputs. No provider.

## Fail-closed behavior

- `authority.can_public_post`/`can_spend`/`can_message_users` `True` is never propagated into a wider `allowed_authority` set than the compiling `Goal` already declared — compile can only narrow.
- `live_authorized=False` → any authority requiring a live route is excluded from the compiled constraints regardless of `authority` fields.
- Missing `availability` entry for a platform → treated as unavailable.
- `budgets` containing a nonzero external-effect figure never survives compilation (forced to `0`).

## Tests (focused + adversarial)

1. `authority` with all fields `False` (the loop's real state) compiles to constraints with no public/spend/message authority, regardless of goal input.
2. `live_authorized=False` excludes any live-route-dependent authority even if goal/authority would otherwise allow it.
3. missing platform in `availability` → excluded from allowed platforms in the compiled constraints.
4. `budgets` with a nonzero external-effect value is zeroed in the compiled output, never passed through.
5. compiling twice with identical inputs yields identical `PlannerConstraints` (deterministic, no hidden state).
6. persona-scope: constraints compiled for persona A never read persona B's availability/budgets.
7. a goal whose own `allowed_authority` is narrower than what `authority`/`availability` would allow stays narrow (compile only narrows).
8. malformed `authority` object (missing an expected field) raises before producing a wider-than-safe default.
