## Deterministic vs model responsibility

Pure counting/comparison against a `PlanDAG`. No provider.

## Fail-closed behavior

- `len(dag.tasks) > limits.max_tasks` → error; the DAG is never truncated silently by this function (truncation, if any, happens at generation time in SB-S22-002 — `enforce` only reports).
- Any task `depth > limits.max_depth` → error.
- Distinct `SPECIALIST`-kind tasks implying concurrent workers beyond `limits.max_workers` → error.
- Any nonzero `budget.model_calls` beyond `limits.max_model_calls` (default `0`) → error.
- Any nonzero `budget.external_effects` → error regardless of `limits` (external effects are always `0`, per spec ground rule 4).

## Tests (focused + adversarial)

1. DAG at exactly `max_tasks` → `[]`; one over → error naming the count.
2. task at `max_depth` → `[]`; one over → error.
3. worker count at `max_workers` → `[]`; one over → error.
4. `model_calls` at `max_model_calls` (`0` by default) → `[]`; any nonzero → error.
5. `external_effects` nonzero anywhere → error, independent of `limits` values (cannot be raised by configuration).
6. `enforce` on the empty DAG → `[]`.
7. multiple simultaneous violations (over tasks and over depth) both reported in the same call, not just the first.
8. `enforce` never mutates `dag`.
9. persona-scope: enforcing limits for one persona's DAG never inspects another persona's plan.
10. adversarial: a DAG built to look small (few top-level tasks) but with deep hidden dependency chains still trips `max_depth` — limits cannot be evaded by shape.
