## Deterministic vs model responsibility

Deterministic adapters only in this harness (`provider=None`). A separate LIVE run with a manifest is out of scope and recorded as a gate in `SB-V23-003`.

## Fail-closed behavior

- Any stage failure → `REJECTED`, lease released, sandbox retired with `keep=[]`, failure receipt written; parent state hash unchanged.
- Adapter raising → caught at RUN, result `FAILED`, then REJECT path; the exception text is in the receipt, not swallowed.
- Timeout → `TIMED_OUT` → REJECT.
- Lease acquisition failure (`LeaseHeld`) → no sandbox created, record shows CREATE failed.
- The runner refuses to write a bundle if any `LifecycleRecord.lease_released` is False or any scratch dir remains.

## Tests (focused + adversarial)

1. Three concurrent workers (researcher A, analyst A, writer B) → all ADOPTED; receipts per worker; scratch root empty; no leases.
2. One worker's adapter raises → that one REJECTED with failure receipt; the other two unaffected; parent state hash identical.
3. Malformed result (adapter writes an output outside scratch) → REJECTED at VERIFY.
4. Worker attempting `EffectGuard.attempt("publish")` → `effect_attempts=1` → REJECTED.
5. Worker attempting `spawn_specialist` → `ChildSpawnDenied` → REJECTED.
6. Persona isolation under concurrency: worker for persona B tries to read persona A's context file by path → `SandboxEscape`; A's outputs untouched.
7. Deadline 0s worker → TIMED_OUT → REJECTED; cleanup complete.
8. Re-running the same `worker_id` after RETIRE → CREATE fails (`SandboxError`/`LeaseHeld` semantics), no second lifecycle.
9. Lease released check: `leasing.inspect(f"specialist:{worker_id}")` is None or stale after every record.
10. Bundle manifest hashes verify; `classification == "fixture"`.
11. `max_workers` cap: 5 contracts with `max_workers=3` → at most 3 concurrently active sandboxes (assert via a counter in a test adapter).
