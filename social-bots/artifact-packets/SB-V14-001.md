## LEAD-014 finding

Submitted `runtime/audience.py` had no bot/persona field on `Hypothesis` and persisted under `memory/<bot>/audience/`. That did not satisfy the isolation requirement.

## LEAD-017 repair review

The `b9899e5a...` repair meaningfully improves the artifact:
- persistent bot/persona scope exists;
- save/load/list are persona-scoped;
- private hypotheses use `memory/<bot>/audience/<persona>/`;
- contradictions no longer become positive support for arbitrary fork statements.

Two privacy/isolation gaps remain:

1. **The allowlist still contains open-ended `audience_interest`, while value filtering only rejects exact sensitive tokens.** A segment such as `{"audience_interest": "religious_interest"}` or `{"audience_interest": "health_interest"}` bypasses the exact-value set despite representing the kind of sensitive profiling this artifact must prevent. Prefer content-topic/context fields whose semantics are safe by construction; if any free-form interest field remains, validate normalized/tokenized values and explicitly prohibit sensitive-trait inference.

2. **`fork_hypothesis(..., persona=...)` can re-scope a fork to another persona while copying the source hypothesis ID and contradiction provenance.** That creates an implicit cross-persona private-memory transfer path. Remove cross-persona re-scope from the normal private fork API, or require a separate explicit shared/import contract that does not reuse private evidence by default.
