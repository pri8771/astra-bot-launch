# Artifact packet — SB-V05-001

Artifact: Machine-captured current-source receipt collector
Milestone: V0.5
Lane: Intelligence / Evidence Integrity
Story points: 3
Current status: CHANGES_REQUIRED after LEAD-017 review.

## Goal

Replace caller-declared "live-capture" provenance with collector-generated, operationally trustworthy evidence.

## Receipt minimum

Each capture stores:
- source URL or canonical source identifier;
- retrieval timestamp;
- retrieval status/result;
- collector version/identity;
- response/content hash;
- extracted evidence used by the bot;
- safe provenance classification created by the collector;
- failure/partial-capture state;
- explicit extraction validity/status;
- no secrets/private browser state.

## Operational trust boundary

Operational-live provenance may be produced only by a **closed collector-owned transport path**.

It is not sufficient for a caller to:
- set `mode="live"`;
- set `operational=True`;
- call a public registration function on its own class;
- subclass a trusted implementation and inherit/obtain trust;
- construct a receipt-like object or hand-written dictionary.

A test-only dependency-injection seam may exist, but it must be structurally incapable of granting operational-live status outside explicit test/fixture mode.

## Live retrieval safety

For an operational HTTP(S) collector:
- allow only validated public HTTP(S) destinations;
- reject loopback/private/link-local/multicast/reserved/unspecified destinations, including IPv4-mapped IPv6 forms;
- reject credentials embedded in URLs;
- validate every redirect and the final destination;
- prove the actual HTTP implementation handles 30x redirects through the validation path, not only a mocked/overridden helper;
- address or explicitly fail closed on DNS validation-to-connect TOCTOU/rebinding so a hostname cannot validate as public and later connect to a private/local address;
- bound redirects, response size and timeouts.

## Extraction safety

Transport success and extraction success are separate facts.

An extraction failure/empty extraction must be explicit and may not be treated as extracted factual support.

## Downstream bridge

The normal operational bridge from a capture receipt into a Social Bots research signal must require operationally trusted evidence.

A verified-but-untrusted capture, fixture capture, or test-only capture may not silently enter the same operational signal path merely because its bytes/hash are valid. If conversion for tests is needed, use an explicitly test-only/fixture path and preserve that status end-to-end.

## Acceptance

- a caller cannot arbitrarily mark a hand-written dictionary as live machine capture;
- an arbitrary caller-defined fetcher cannot become operational-live merely through attributes, subclassing, or public self-registration;
- only the closed collector-owned operational transport can produce `is_operational_live_evidence()==True`;
- the normal operational signal bridge rejects fixture/untrusted captures;
- same source captured twice yields separate retrieval receipts but stable content hash when unchanged;
- changed content yields changed hash;
- failed/partial/empty retrieval cannot be presented as verified current evidence;
- unsafe initial destinations are rejected before contact;
- unsafe redirect/final destinations are rejected before contact;
- the real HTTP redirect handling path has a regression proving 30x responses flow through redirect validation;
- DNS rebinding/validation-to-connect risk is closed or the live path fails closed where the implementation cannot guarantee the validated address is the connected address;
- extraction failure cannot be used as extracted factual support;
- tests use explicit fixtures and never masquerade as operational capture.

## LEAD-017 findings

The `ecad87e6` repair was directionally strong but not yet acceptable:
1. `register_trusted_transport(cls)` is public and mutable; the test suite itself registers a caller-created `TrustedLiveStub`, which then obtains operational-live status. This is self-certification through a registry rather than collector-owned trust.
2. `to_signal()` accepts any `is_verified_capture()` and therefore permits verified-but-untrusted live receipts into the normal signal bridge.
3. redirect tests override `_perform()` and do not prove the actual urllib 30x behavior; DNS is also resolved once for validation and again later by the socket connection.
