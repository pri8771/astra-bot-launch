# Artifact packet — SB-V05-001

Artifact: Machine-captured current-source receipt collector
Milestone: V0.5
Lane: Intelligence / Evidence Integrity
Story points: 3
Current status: CHANGES_REQUIRED after LEAD-020 review.

## Goal

Replace caller-declared "live-capture" provenance with collector-generated, operationally trustworthy evidence.

## Receipt minimum

Each capture stores:
- source URL or canonical source identifier;
- retrieval timestamp;
- retrieval status/result;
- collector version/identity;
- response/content hash;
- extracted evidence used by the bot;
- safe provenance classification created by the collector;
- failure/partial-capture state;
- explicit extraction validity/status;
- no secrets/private browser state.

## Operational trust boundary

Operational-live provenance may be produced only by a **closed collector-owned transport path**.

It is not sufficient for a caller to:
- set `mode="live"`;
- set `operational=True`;
- call a public registration function on its own class;
- subclass a trusted implementation and inherit/obtain trust;
- construct a receipt-like object or hand-written dictionary.

A test-only dependency-injection seam may exist, but it must be structurally incapable of granting operational-live status outside explicit test/fixture mode.

## Live retrieval safety

For an operational HTTP(S) collector:
- allow only validated public HTTP(S) destinations;
- reject loopback/private/link-local/multicast/reserved/unspecified destinations, including IPv4-mapped IPv6 forms;
- reject credentials embedded in URLs;
- validate every redirect and the final destination, or deliberately fail closed on redirects and document that posture;
- address DNS validation-to-connect TOCTOU/rebinding by ensuring the socket actually connects to the already validated/pinned public address rather than re-resolving the hostname later;
- bound redirects, response size and timeouts.

For **HTTPS specifically**, pinned-address safety must not disable normal TLS identity protections:
- the TCP connection must use the validated/pinned public IP;
- TLS SNI and certificate hostname verification must still use the original validated hostname;
- the Host header must preserve the original hostname semantics;
- do not use an unsupported stdlib constructor argument or another path that silently falls back to hostname DNS resolution.

## Extraction safety

Transport success and extraction success are separate facts.

An extraction failure/empty extraction must be explicit and may not be treated as extracted factual support.

## Downstream bridge

The normal operational bridge from a capture receipt into a Social Bots research signal must require operationally trusted evidence.

A verified-but-untrusted capture, fixture capture, or test-only capture may not silently enter the same operational signal path merely because its bytes/hash are valid. If conversion for tests is needed, use an explicitly test-only/fixture path and preserve that status end-to-end.

## Acceptance

- a caller cannot arbitrarily mark a hand-written dictionary as live machine capture;
- an arbitrary caller-defined fetcher cannot become operational-live merely through attributes, subclassing, or public self-registration;
- only the closed collector-owned operational transport can produce `is_operational_live_evidence()==True`;
- the normal operational signal bridge rejects fixture/untrusted captures;
- same source captured twice yields separate retrieval receipts but stable content hash when unchanged;
- changed content yields changed hash;
- failed/partial/empty retrieval cannot be presented as verified current evidence;
- unsafe initial destinations are rejected before contact;
- redirects either revalidate/re-pin every hop through the real path or fail closed honestly;
- DNS rebinding/validation-to-connect risk is closed: the actual socket connects to the validated/pinned address;
- HTTPS pinned-IP retrieval preserves original-host SNI/certificate verification and Host semantics;
- extraction failure cannot be used as extracted factual support;
- tests use explicit fixtures and never masquerade as operational capture;
- at least one regression exercises the **production HTTPS connection-construction path** enough to catch invalid stdlib API usage, rather than proving only mocked/overridden helpers.

## LEAD-017 findings — repaired directionally

Earlier repair gaps included public transport self-registration, verified-but-untrusted receipts entering the operational bridge, redirect overclaiming and DNS validation/connect separation. The latest worker repair materially improved those boundaries through static/internal trust, evidence classes, bridge gating, pinned-address design and fail-closed redirects.

## LEAD-020 remaining finding

Independent source review found the actual live HTTPS path still cannot succeed:

`UrllibFetcher._perform()` invokes stdlib `http.client.HTTPSConnection(..., server_hostname=pinned.host)`, but the constructor does not accept a `server_hostname` keyword. The resulting exception is converted into a failed receipt, so fixture/stub tests do not prove operational HTTPS works.

Required repair before resubmission:
1. implement valid pinned-IP HTTPS while preserving original-host SNI and certificate verification;
2. keep the actual socket bound to the previously validated public IP with no hostname re-resolution gap;
3. preserve correct Host header semantics;
4. add a regression that exercises the real connection-construction path and would fail on an unsupported constructor signature;
5. preserve the latest static trust, operational bridge, redirect fail-closed and extraction-status controls.

Expected return status: SUBMITTED for another lead audit.
