## Separate reproduced defect

Accepted source under diagnosis: **`3f10d0f6eb031c00fff679aae18aa8045d8bd025`**  
Native diagnostic/evidence: **`63bb73fffe7de1b52e551e952d7ed7d9531c4675`**, `social-bots/lead-reviews/CODEX_ROUTE_SCHEMA_20260922.md`.

The documented registry schema restricts `route_type` to:

- `API`
- `browser`
- `Buffer`
- `manual`
- `unsupported`

The current `load_routes()` validates that `route_type` exists but does not validate enum membership. `_route_ok()` rejects only the literal `unsupported`. Therefore a synthetic route with `route_type="telepathy"`, healthy status, current verification and draft capability is admitted as account-available and draft-authorized.

Root cause is a schema validation gap at registry ingest, not route-selection policy and not provider connectivity.

## Smallest authorized repair

Codex may implement the following in a separate isolated repair branch:

1. Add an explicit allowed-route-type enum/set matching `ACCOUNT_REGISTRY_SCHEMA.md` exactly:
   `API | browser | Buffer | manual | unsupported`.
2. In `load_routes()`, reject the **entire registry** with `RouteRegistryError` if any route has a `route_type` outside that enum.
3. Preserve `unsupported` as a valid parsed route type; it remains unavailable through the existing route eligibility gate.
4. Preserve all accepted LEAD-056/057/058 freshness, exact-scope, unique-eligible, ambiguity, capability and community behavior.
5. Do **not** introduce a new boolean-schema/type contract for fields where the documented schema does not require one.
6. Add deterministic tests proving:
   - unknown route type causes whole-registry rejection;
   - a mixed registry containing one valid route plus one unknown-type route is rejected as a whole;
   - each documented supported type parses;
   - `unsupported` parses but remains unavailable/unauthorized;
   - existing secret rejection and route selection/freshness behavior remain intact.
7. Reproduce red-before/green-after and run route/community/affected/full suites.
8. Return exact SHA, commands/exits, evidence refs and limitations for ChatGPT formal review.

No real account/provider/network/model/public/scheduler/host action is authorized.
