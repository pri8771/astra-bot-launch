### SB-V03-005 — CHANGES REQUIRED, narrow migration repair

The RuntimeState / PersonaState split is the correct architecture and the primary isolation defect is repaired:
- consumed signals are persona-private;
- hypotheses are persona-private;
- reasoning hypothesis count is persona-private;
- same shared evidence can be independently considered by multiple personas.

Remaining migration consistency issue:
- decision.run_cycle loads RuntimeState before PersonaState;
- PersonaState legacy migration may persist `_legacy.migrated_to_persona=true` through a fresh RuntimeState, while the older in-memory RuntimeState can later save its stale false marker over it;
- migration marks the runtime migrated before the new persona file is durably saved, creating a crash window where the marker can say migrated while the active persona file is absent.

Required narrow repair:
1. make legacy migration crash-safe/idempotent;
2. persist persona state before final migrated marker, or otherwise use recoverable two-phase semantics;
3. ensure the RuntimeState instance subsequently committed by run_cycle contains the final marker;
4. add a regression covering the real run_cycle load/save ordering;
5. add crash/interruption simulation between persona save and marker update where practical.

After this narrow repair, generate SB-V03-006.

## Intelligence audit

### SB-V05-001 — CHANGES REQUIRED, trust boundary not yet closed

Improvements verified:
- extraction validity;
- obvious private/loopback destination rejection;
- manual redirect validation structure;
- untrusted live fetcher does not automatically become operational live.

Remaining:
1. `register_trusted_transport()` is a public mutable registration API; ordinary in-process callers/tests can register arbitrary classes as trusted. Trust must be policy-owned/static, not caller-grantable.
2. operational downstream bridges must distinguish fixture/verified-untrusted from operational trusted-live evidence. A merely verified receipt must not silently become operational evidence.
3. DNS validation and network connect separately resolve the hostname, leaving a DNS-rebinding/TOCTOU gap. The trusted live transport must pin/use a validated public address for the actual connection or otherwise prove equivalent protection.
4. redirect tests currently override `_perform`; real urllib 30x behavior is not proven. Either correctly handle/test actual redirect responses or deliberately fail closed on redirects and document that limitation.

### SB-V05-002 — CHANGES REQUIRED, operational semantic review not yet trustworthy

Improvements verified:
- caller-supplied stance no longer directly grants support;
- assessor identity/version recorded;
- omitted numeric/year/marker claims can be identified and withheld.

Remaining:
1. `register_operational_assessor()` is another public mutable trust registry; caller code can self-register an arbitrary assessor.
2. `KeywordSupportAssessor` is too weak to be an operational arbitrary-fact verifier: key-term co-occurrence does not establish proposition, negation, quantities, units, subject/object relationships or entailment.
3. the heuristic claim extractor misses many material factual claims without its markers/numbers (for example ordinary factual declarative sentences).
4. `evidence_ref_from_receipt()` accepts any verified fixture/untrusted receipt; operational review must require trusted operational evidence while fixtures remain explicitly test-only.

Required direction:
- preserve the assessor/extractor interfaces;
- make heuristic/manual implementations diagnostic/test-only;
- operational semantic assessor/claim extractor must be policy-owned and fail closed when unavailable;
- prefer reuse of the Core adaptive reasoning/provider infrastructure once accepted instead of building a second model gateway.

Intelligence should not block all progress on the model dependency: after closing trust-mode boundaries, continue V13/V14/V15/V16/V17/V20-002 while the operational semantic assessor remains explicitly BLOCKED on the accepted adaptive-provider integration.
