## Windows Core audit

### SB-V03-004 — CHANGES_REQUIRED

Positive verified source findings:
- the LEAD-019 legacy-migration defect is repaired in `175f741...`;
- `PersonaState.load()` stages migration in memory without durable writes;
- decision/state/content/experiment/action writes are assembled and committed inside `Fence.fenced_commit()`;
- `Fence.fenced_commit()` checks lease identity + monotonically increasing generation while holding the same per-task lock used by takeover.

New LEAD-024 defect:

`runtime/worker.py::run_one_unit()` calls `decision.run_cycle(..., fence=fence)`, but after the fenced cycle returns it writes the `finish` receipt outside the fence. A worker can therefore:
1. successfully finish the fenced cycle commit;
2. stall;
3. let its lease expire;
4. lose ownership to a new generation;
5. resume and write a finish receipt claiming `candidate_succeeded=true` / verified success despite no longer owning the task.

The SB-V03-004 packet explicitly requires that an old owner that loses/expires its fence cannot commit receipts that imply success after takeover. This remains an acceptance blocker even though the underlying cycle commit is fenced correctly.

Required repair:
- fence or atomically ownership-check all durable post-cycle success/finish receipt writes;
- add an adversarial post-cycle-stall -> TTL expiry -> takeover -> old-owner-resume regression;
- prove the obsolete owner cannot emit success-implying finish evidence;
- do not fix by merely increasing TTL.

### SB-V03-005 — CHANGES_REQUIRED

Positive worker submission at `d1e4bee...`:
- `PERSONA_SCOPED_READERS` covers all six persona-scoped stores;
- `persona_records(bot, persona, store)` provides one authoritative persona facade;
- `admin_all_records()` explicitly names the intended whole-runtime admin/audit path;
- generic mixed-persona regressions verify strict filtering and partition coverage;
- production content dedup already uses persona-scoped `persona_content_keys()`.

Remaining lead finding:

The submission documents raw enumeration as admin-only, but it does not structurally make the underlying raw APIs admin-only or prove all normal production readers are routed through the facade. Examples still visible on the runtime surface include `pipeline.publish_queue(bot)` and `analytics.events_for(bot)`, both whole-runtime readers with non-admin names, plus direct append-only store reads. A persona-facing production caller can still bypass `persona_records()` unless every real call site is constrained by convention.

The artifact packet requires production-path enforcement, not only a safe facade plus tests of that facade.

Required repair:
- route actual persona-facing production read/list call sites through the persona boundary;
- make necessary raw whole-runtime APIs explicitly private/admin/internal (or enforce an equivalent structural boundary);
- retain intentional runtime-wide admin/reconciliation paths separately;
- test actual production reader paths for mixed-persona no-bleed, including experiment, analytics/history, publish queue, decisions/actions and content where applicable.
