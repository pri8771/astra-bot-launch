## Artifact review — SB-V05-001

Disposition: **CHANGES_REQUIRED**.

The worker substantially improved the artifact:
- caller-declared `mode="live"` alone no longer grants live provenance;
- public URL validation rejects obvious private/loopback/link-local/multicast/reserved/unspecified destinations;
- redirect targets are intended to be revalidated;
- extraction validity is explicit;
- failed extraction is kept out of extracted factual support;
- worker reports 139 local tests, and the committed evidence remains fixture-labelled rather than falsely operational.

However, independent source/test review found a remaining trust-boundary defect that directly violates the packet wording “collector-owned trusted transports”.

### Finding 1 — trust can still be granted by an arbitrary caller

`runtime/collector.py` exposes `register_trusted_transport(cls)` as a public function and stores trusted classes in mutable module-global `_TRUSTED_TRANSPORT_CLASSES`.

The acceptance tests themselves demonstrate the bypass:

```python
@collector.register_trusted_transport
class TrustedLiveStub:
    mode = collector.MODE_LIVE
    ...
```

That caller-created class then produces:
- `transport_trusted == True`
- `provenance == "live-capture"`
- `is_operational_live_evidence() == True`

So the repair moved self-certification from `Fetcher.mode` to a public registration call; it did not yet make operational trust collector-owned/closed.

Required repair:
- operational trust must come from a closed collector-owned allowlist/capability, not a public arbitrary-class registration API;
- tests may use an explicit fixture/test-only injection seam, but test registration must never be reachable as the operational trust mechanism;
- add a regression proving arbitrary runtime code cannot register a custom live fetcher and obtain operational-live evidence.

### Finding 2 — operational bridge still accepts untrusted live captures

`to_signal()` currently accepts any `is_verified_capture()` receipt, including a receipt whose provenance is `unverified-untrusted-transport`, and turns it into a normal `research.Signal`.

Required repair:
- the operational bridge must require trusted operational evidence, or make fixture/untrusted conversion an explicit test-only path that cannot be mistaken for operational current evidence;
- do not rely on a string provenance label if downstream signal consumers do not enforce it.

### Finding 3 — real redirect/DNS safety is not fully proven

The redirect tests override `_perform()` and therefore prove the fetch-loop policy, not the real `urllib` redirect behavior. With `_NoRedirect.redirect_request()` returning `None`, Python urllib can surface a 30x as `HTTPError` rather than a normal response, which may bypass the intended manual redirect branch. In addition, destination validation resolves DNS before connection, while the actual socket connection may resolve again; DNS-rebinding/TOCTOU is not addressed.

Required repair/evidence:
- add at least one test around the real `_perform()` redirect handling path (local fake opener/HTTPResponse is fine; no external network required) so 30x headers are actually consumed as `_Redirect` rather than generic failure;
- document and, where reasonably possible, close DNS rebinding/validation-to-connect TOCTOU before calling the live path SSRF-safe.

## Artifact review — SB-V05-002

Disposition: **CHANGES_REQUIRED**.

The follow-on repair at `cbd781ca...` is useful but advanced before its SB-V05-001 evidence dependency was accepted. It adds:
- an attributable `SupportAssessor` interface;
- material-claim identification/reconciliation so caller omission no longer trivially bypasses gating;
- explicit non-operational manual/fixture assessments;
- source hash staleness and support status vocabulary.

Independent review found three blockers.

### Finding 1 — assessor authority repeats the self-registration problem

`runtime/factcheck.py` exposes public mutable `register_operational_assessor(cls)` backed by `_OPERATIONAL_ASSESSOR_CLASSES`.

That recreates the SB-V05-001 flaw: arbitrary runtime code can define its own assessor, call the registration function and cause its assessments to be marked operational. Exact-class matching prevents accidental subclass inheritance but does not prevent deliberate self-registration.

Required repair:
- close operational assessor authority behind a module/configuration-owned allowlist/capability;
- preserve a structurally test-only injection seam for fixtures;
- add a regression proving arbitrary code cannot self-register an assessor and grant operational support.

### Finding 2 — evidence bridge accepts verified fixture/untrusted captures

`evidence_ref_from_receipt()` checks only `receipt.is_verified_capture()`. The current tests create evidence refs from `FixtureFetcher` captures and then allow those refs through the same fact-review path.

Fixtures are valid for unit tests, but the operational factual-review path must require an evidence receipt accepted under SB-V05-001's operational trust boundary. A verified hash alone is not enough.

### Finding 3 — keyword co-occurrence overclaims factual support

`KeywordSupportAssessor` is marked operational and returns full `SUPPORTS` whenever all key terms from the claim occur in the excerpt. That does not establish the asserted relationship, value or negation.

Examples that must fail safely include:
- same terms with opposite meaning/negation;
- same terms but unrelated relationship;
- numeric/date mismatch;
- excerpt mentions the subject without supporting the predicate.

The deterministic assessor may remain as a conservative helper, but it should return PARTIAL/UNKNOWN/UNSUPPORTED when it cannot safely establish the proposition. Full factual support must not be granted by token co-occurrence alone.
