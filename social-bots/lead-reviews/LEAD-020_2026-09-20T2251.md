### SB-V05-001 — live source collector

Disposition: **CHANGES_REQUIRED**.

The LEAD-018 trust-boundary repair is directionally strong: operational transport trust is now static/internal, fixtures are distinguished from trusted-operational evidence, operational bridges fail closed, public destinations are validated and pinned, and redirects deliberately fail closed.

However independent source review found a real live-path defect in `UrllibFetcher._perform()`:

`http.client.HTTPSConnection(..., server_hostname=pinned.host)` is used while the stdlib `HTTPSConnection` constructor does not accept a `server_hostname` keyword. The call therefore fails before a trusted HTTPS retrieval can occur, and `fetch()` converts that exception into a failed receipt.

Required repair:
1. implement pinned-IP HTTPS while preserving hostname SNI and certificate verification using a valid stdlib mechanism;
2. keep the actual socket bound to the previously validated public IP (no DNS re-resolution gap);
3. add a regression that exercises the real HTTPS connection-construction path so an unsupported constructor signature cannot pass;
4. preserve static trust, operational bridge gating and fail-closed redirects.

Do not present fixture transport tests as proof that trusted live HTTPS works.
