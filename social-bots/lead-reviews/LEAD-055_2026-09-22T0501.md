## Newly reproduced V1.3 metrics defect

At exact current source `9d497b4...`, bounded synthetic diagnostics reproduced that normalized metrics accept **bool, NaN and ±infinity** as `PRESENT` because `bool` is an `int` subclass and the code accepts any `int|float`. Those invalid values are persisted and aggregation can propagate NaN/nonfinite results. Existing 21 metric tests do not cover these cases.

### Root cause

- `runtime/metrics.py::normalize` uses `isinstance(raw_value, (int, float))` without excluding bool or nonfinite floats.
- `aggregate_semantic` likewise trusts stored `PRESENT` numeric-looking values and can consume legacy invalid observations.

### Bounded Codex repair RELEASED

**Codex is authorized to implement this exact SP1 repair directly in an isolated repair branch. No Fable handoff.**

Required repair scope:

1. In `runtime/metrics.py`, treat a mapped raw metric as PRESENT only when it is an **int/float, not bool, and finite**.
2. Invalid mapped values remain **MISSING**, never zero; retain the original raw value in `raw_metrics`, retain raw-name/provenance context and expected metric kind.
3. Defensively make `aggregate_semantic` exclude legacy stored PRESENT values that are bool/non-numeric/nonfinite rather than allowing NaN/inf propagation. Count/report them through the existing missing/excluded semantics without fabricating zero.
4. Add focused regressions for bool, NaN, +inf, -inf through normalization, persistence/reload and aggregation; prove aggregate outputs remain finite and valid normal numeric zero still remains PRESENT.
5. Preserve current MISSING/NOT_SUPPORTED semantics, raw provenance, persona scoping and metric-kind behavior.
