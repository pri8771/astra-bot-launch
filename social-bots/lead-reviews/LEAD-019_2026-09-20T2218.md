## Reconciliation — SB-V03-004

Disposition: **CHANGES_REQUIRED** (reopened after LEAD-018).

LEAD-018 accepted the final `Fence.fenced_commit` region and correctly observed that decision history/latest-decision writes were moved inside that region. That is a real improvement.

However, deeper source review found worker-owned durable state writes that occur **before** the fenced commit:

- `decision.run_cycle()` calls `RuntimeState.load(bot)` and `PersonaState.load(bot, persona_id)` before `_commit()`.
- `PersonaState.load()` can perform migration and call `obj.save()` immediately.
- `_migrate_from_legacy()` can update the runtime migration marker and call `rt.save()` immediately.

Those writes are triggered by the active cycle and are durable state writes. A stale worker can therefore enter a legacy migration path, lose ownership, and still leave migration/persona state behind before the final fence rejects it.

This directly conflicts with the current SB-V03-004 packet:
> an old owner that loses/expires its fence cannot commit state ... afterward.

Required repair:
1. cycle state loading/migration becomes side-effect free;
2. migration persistence is staged inside the ownership-fenced commit or separately fenced before any durable write;
3. adversarial regression forces stale-owner takeover during legacy migration and proves the old owner leaves no durable migration/persona write;
4. preserve the existing corrected guarantee language: ownership fencing, not ACID transactionality.

Windows/WSL host portability remains a separate SB-V07-WIN-001 acceptance concern, but the migration write itself is part of V03-004 because it violates the ownership-fencing contract.

- cumulative snapshots reduce to latest-per-series instead of summing over time;
- snapshot-to-delta derivation checks comparable series and records provenance;
- 100 then 150 snapshot regression no longer produces 250.

Remaining correctness gaps:

1. **Supported-but-missing metrics lose known semantic kind.**
   When a platform mapping knows SAVE/REACH/etc. is cumulative/delta/gauge/rate but the raw metric is absent, the emitted MISSING value currently carries `metric_kind=None`. Downstream compatibility should retain the expected kind when known.

2. **Delta aggregation blindly sums duplicate/overlapping windows.**
   `aggregate_semantic()` sums every PRESENT delta entry. Duplicate or overlapping windows for the same series can therefore double-count. Summation must require compatible/non-overlapping windows or explicit source semantics.

Required regressions are now in the canonical SB-V13-001 packet.
