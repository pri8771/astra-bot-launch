## What was built

Per `STRATEGY_SCHEMA.md` / spec §2.1 and the packet:
- `StrategyState` frozen dataclass (schema_version 1) with strict `from_dict` (unknown/missing keys are errors) and `validate_state` (bot ∈ `paths.BOTS`, persona regex, contiguous `supersedes`, status enum incl. the S21 lifecycle values, confidence ∈ [0,1] or None, ISO dates, provenance `fixture|evidence`).
- Weight maps: non-negative, finite, sum to 1.0 ± 1e-6 (or empty = none defined); evidence refs must be dicts (`evidence_id` or `kind`+`id`), never bare numbers/strings.
- Store: `state/<bot>/strategy/<persona>/v%04d.json` (immutable; `StrategyVersionExists`), `HEAD.json` pointer, `HISTORY.jsonl` with the file's sha256; `save_version` refuses any version other than latest+1 and any `supersedes` not stored (`StrategyVersionGap`); `history()` re-hashes and flags `tampered`/`missing` instead of repairing.
- Fenced commits: `save_version(..., activate=True, fence=...)` and `set_active(..., fence=...)` run version → HISTORY → HEAD inside one `leasing.Fence.fenced_commit`; a lost fence writes nothing.
- `next_version` only accepts `MUTABLE_FIELDS` (no arbitrary dict merge). Reads never create directories (`strategy_dir(create=False)` default) so `admin_all_strategies` cannot list phantom personas; `admin_all_strategies` is the only cross-persona reader.
