## What was built

- `RestrictedView`: a sandbox view whose `write` accepts exactly one path (the role's result file) and raises `WriteDenied` for anything else, including `inputs/` and `context/`. Adapters never hold the raw sandbox write path.
- `Bundle`: parses `inputs/` + `context/` JSON, records sha256 of every input file, indexes evidence ids from `EvidenceCapture/1` (status ok) and `ResearchResult/1`; unreadable files are surfaced as limitations, not hidden.
- `AnalystSpecialist` → `AnalysisResult/1`: one deterministic finding per resolvable ok evidence ref with `confidence=None` (unknown is not zero); optional `BudgetedProvider` findings are kept only when their evidence resolves, otherwise moved to `unsupported_claims`; malformed provider items and out-of-range confidence are neutralised; `WorkerResult.evidence_refs` = refs cited by findings.
- `ReviewerSpecialist` → `ReviewResult/1`: pure `integrity_issues(bundle)` (unsupported finding, unsupported/uncovered draft claim, draft status ≠ `DRAFT_UNPUBLISHED`, malformed docs); verdict `PASS` / `FAIL` / `NEEDS_EVIDENCE` (no reviewable inputs); a provider can add `provider_issue` entries but can never flip a deterministic `FAIL` to `PASS`, and provider issues on a deterministic `PASS` yield `NEEDS_EVIDENCE` (a model may ask, not assert); `reviewed_sha256` recorded for every input file.
- Both: role/contract/sandbox/provider identity checks, refuse to run on failed context, honour tool narrowing, deadline checks → `TIMED_OUT`, single result-file output with sha256.

## Limitations

- Reviewer coverage rule is evidence-id based (a claim is covered when some finding cites the same evidence); it does not judge prose.
