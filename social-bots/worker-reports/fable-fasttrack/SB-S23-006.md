## What was built

- `verify(result, contract, sandbox) -> list[str]`: `validate_result` plus sandbox identity, adoptable state (`COMPLETED` only), context not failed, every declared output present in scratch with matching sha256 and matching in-file `schema`, `ReviewResult` `reviewed_sha256` still matching the reviewed inputs, `DraftResult` candidate `DRAFT_UNPUBLISHED`. Any error ⇒ reject.
- `adopt(result, contract, sandbox, *, bot, persona, fence=None, keep=None)`: scope check and `verify()` precondition before any write; inside one `Fence.fenced_commit` (when given) the sandbox is retired keeping only declared outputs (copied to `receipts/<bot>/specialists/<worker_id>/` with `INDEX.json`) and a sanitized receipt is written; returns `AdoptionReceipt` with kept paths and hashes. A lost fence runs nothing; scratch stays for `reject`.
- `reject(result, contract, sandbox, reasons)`: failure receipt with the reasons, then retire with `keep=[]`; parent state untouched.
- `integrate_into(kind, adopted)`: deterministic mapping returning values only: `ResearchResult/1` → ok evidence refs; `DraftResult/1` → candidate (status must be `DRAFT_UNPUBLISHED`, else error) + claims; other schemas → reference to the kept file. Never writes `PersonaState`/`RuntimeState`/content/experiments.
- Deviation from the spec text, documented in the module docstring: `receipts.write_receipt` (Cursor-owned) only accepts `start|finish|failure`, so adoption uses `finish` and rejection `failure` with `detail["specialist"]` carrying the decision, under task id `specialist:<worker_id>` (the lease key SB-S23-008 uses).

- Receipt kinds reuse the existing `finish|failure` vocabulary (see deviation above).
