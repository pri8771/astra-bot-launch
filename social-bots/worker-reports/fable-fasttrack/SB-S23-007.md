## What was built

- `WorkerLedger`: per-worker deterministic `calls_used` / `effect_attempts` / events; adapters copy these into `WorkerResult`.
- `Deadline`: monotonic budget from `contract.time_budget_s` with an injectable clock; `check()` raises `DeadlineExceeded`; `budget_s <= 0` is already expired.
- `BudgetedProvider(provider, contract, *, artifact, lane, run_scope, manifest_dir, ledger, deadline)`: the only provider path for specialists. Fixture providers (`adaptive` false) need no manifest and never count as live. An adaptive provider object is treated as a live route **regardless of `SBOTS_REASONING`**: posture (`ANTHROPIC_API_KEY`) then `authorization.authorize` must succeed or construction raises `ProviderNotAuthorized` and the wrapped provider is never called. Effective budget is `min(contract.model_call_budget, grant.max_calls)`. `propose()` refuses another persona/bot (`ScopeMismatch`), checks the deadline, counts before delegating (a raise still consumes a slot), and raises `CallBudgetExhausted` at the budget. `live_route_guard.check` is recorded in the ledger for receipts but is not the gate, because it keys on the env mode (the SB-R07-041 bypass class).
- `SpawnGuard`: `assert_no_child` (spawn tools), `assert_tool_allowed` (allowlist/denylist), `depth_of` / `assert_depth` (a contract whose `parent_run_id` is a worker id is depth 2 and refused).
- `EffectGuard.attempt`: always denies, records the attempt so `validate_result` rejects the result.

## Limitations

- A provider that declares `adaptive=False` but performs a live call would defeat the type-level check; the real providers (`ModelReasoningProvider`, `ClaudeCodeReasoningProvider`) declare `adaptive=True`, and no V2.3 engineering slice wires one. Any real specialist model call still requires a canonical manifest (`SB-V23-003` gate).
- Time budget is wall-clock per process; no CPU/memory limits (V3 process-pool option).
