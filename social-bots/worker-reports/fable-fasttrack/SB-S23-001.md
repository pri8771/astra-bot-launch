## What was built

Schema v2 contract runtime per `SPECIALIST_WORKER_CONTRACT_SCHEMA.md` and spec §2.6/§5.1/§5.2:
- `SpecialistAuthority`: frozen dataclass with exactly `read_context_refs`, `write_scratch`, `emit_result`; no public/spend/message/state/spawn field exists; subclass widening rejected by `validate_authority`.
- `WorkerContract`: frozen; `external_effect_budget` is an `init=False` field fixed at 0 (not a constructor parameter, not reassignable, rejected on reload if non-zero); `schema_version=2`; `scratch_scope == worker_id`.
- `ROLE_TOOLS` allowlists (researcher/analyst/writer/reviewer/media/qa); `ALL_SPECIALIST_TOOLS` disjoint from publish/enqueue/spend/message/update_state/register_experiment/spawn.
- `new_contract`: least-authority constructor; refuses unknown kwargs (`decision.Authority` fields, `authority_scope`, `external_effect_budget`), non-`SpecialistAuthority` authority, tools outside the role allowlist, credential-shaped or authority-widening keys anywhere inside context refs / input artifacts / stop conditions, non-positive budgets/TTL, unsafe ids; returns only contracts with `validate_contract == []`.
- `WorkerResult` (schema v2 incl. `provenance`), strict `from_dict` for both records (unknown/missing keys are errors), `validate_result` (identity/persona match, `effect_attempts == 0`, `calls_used <= budget`, enum states, timestamps, contained relative output paths with sha256, no duplicate outputs).
