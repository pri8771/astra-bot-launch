## Gate rules (what a reviewer should try to break)

1. No dispatch scope → every LIVE callable is refused before invocation. Scopes are installed only by the two entrypoints and the batch executor.
2. Every LIVE dispatch re-runs `authorization.authorize` (canonical scoped manifest, posture incl. `ANTHROPIC_API_KEY`, expiry judged at dispatch) and reserves a durable `CallBudget` slot (`O_CREAT|O_EXCL`) BEFORE the callable runs. Slots are shared across threads, wrappers, processes and restarts; a raise or process death after reservation leaves the slot consumed (`reserved_not_recorded`).
3. Reentry on the same thread is refused; a second thread must win its own slot.
4. Exempt from live accounting only by exact type: `ReceiptReplay`, `EngineeringStub`, and the CLI provider's own injected-runner closure. Subclasses, look-alikes, attributes and `live=False` claims do not exempt. Under a production scope the engineering seams are refused outright.
5. The batch executor reserves first; the provider's own gate adopts that single token (no double consumption); an unadopted token is dropped, never reused.
6. Every dispatch leaves a `DispatchRecord`; the decision record cites it so LIVE_MODEL vs offline evidence never blur.

## Limitations (stated, not waived)

- A declaration that lies in source (an `EngineeringStub` whose body performs a real call, or an injected runner that launches for real outside any production scope) is a reviewable code change, not a runtime bypass; the gate cannot detect it. Under a production scope both seams are refused.
- Batch token adoption is same-thread by design; a provider that dispatches from another thread would reserve its own slot (over-count, the safe direction).
- Parked V2.3 modules (`specialist_budget.py` and siblings) keep their own label-based accounting (LEAD-047 P0 in parked code) and the P1 kept-output hash gap. They are not reachable from the V1.7 dispatcher; a no-dispatch scope-guard test (V1.7 §A6) will prove that. Deferred defects, recorded, not fixed, not claimed secure.
- `model_dispatch.availability()` constructs a `CallBudget`, which creates the empty ledger directory (pre-existing `CallBudget` behaviour).
- Fixture manifests are never a real authorization. This artifact proves refusal and accounting mechanics only; a LIVE_MODEL run of the same route stays BLOCKED_AUTHORIZATION.
