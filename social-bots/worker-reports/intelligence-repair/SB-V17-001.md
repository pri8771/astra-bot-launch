## Scope

Repair of SB-V17-001 community observation/decision/memory per
INTELLIGENCE_WAVE1 §7 and the LEAD-014 finding that `community_signals.jsonl` and
`community_themes(bot)` were bot-wide and `theme_to_audience_evidence()` omitted
persona scope (cross-persona blend risk on shared runtimes).

## Changes (`runtime/community.py`)

1. **Operational read-only signal requires a receipt ref.** `CommunitySignal`
   gains `receipt_ref`; `ingest` refuses `source="read-only-evidence"` without a
   capture/platform `receipt_ref`. `is_operational()` is true only for a
   read-only-evidence signal that carries a receipt ref — a fixture is never
   operational.
2. **Persona/workspace-scoped private memory + themes.** Memory persists under
   `memory/<bot>/community/<persona>/`. `remember`, `signals`, and
   `community_themes` are persona-scoped; `remember` refuses a signal whose own
   persona disagrees with the scope. One persona's signals can never silently
   enter another persona's themes on a shared runtime.
3. **Persona scope on audience evidence.** `theme_to_audience_evidence(bot,
   persona, theme)` now carries the persona/workspace `scope`.
4. **Explicit shared generalization only.** `generalize_theme_to_shared` +
   `shared_community_insights` provide an opt-in shared-insight layer recording
   the origin persona; there is no implicit cross-persona bleed.
5. Preserved: read/observe fully walled from response effect, safety/value gates,
   NO_ACTION for unsafe/low-value, proposal→authority→deterministic review with
   no public effect, and the absence of any engagement/vote/follow/post surface.

No Core files modified.
