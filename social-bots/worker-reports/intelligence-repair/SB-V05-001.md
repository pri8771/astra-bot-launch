## Changes (`runtime/collector.py`)

1. **Trusted-transport gating.** Operational-live provenance is now produced
   only by a *trusted, collector-owned transport*. Trust is granted by explicit,
   auditable registration (`register_trusted_transport` / `is_trusted_transport`)
   — never by a fetcher's own `mode` claim. The receipt records the
   collector-derived `transport_trusted`; `_derive_provenance` returns
   `live-capture` only when `mode==live AND trusted AND status ok`. An arbitrary
   custom fetcher declaring `mode="live"` is downgraded to
   `provenance="unverified-untrusted-transport"` and
   `is_operational_live_evidence()==False`. Trust is keyed on the exact class,
   so a subclass that overrides retrieval does not inherit trust implicitly.

2. **Safe public-destination validation (SSRF defence).** New
   `validate_public_url()` restricts live retrieval to `http`/`https` and rejects
   any destination resolving to loopback / private / link-local / multicast /
   reserved / unspecified addresses (IPv4-mapped IPv6 unwrapped first). Literal
   IPs classify offline (no DNS needed).

3. **Redirect / final-destination validation.** `UrllibFetcher` follows
   redirects manually (auto-follow disabled) and re-validates every hop and the
   final destination before contact, up to `max_redirects`. A public URL that
   redirects to a private/loopback target yields `unsafe-redirect`, not evidence.

4. **`extraction_status` + honesty.** Each receipt carries
   `extraction_status` (`not_attempted`/`ok`/`failed`/`empty`) and an
   out-of-band `extraction_error`. Extraction failures are never placed inside
   `extracted`; downstream consumers gate on `has_usable_extraction()`, so an
   extraction failure can never be used as extracted factual support.

`research.py` and all Core files (`state.py`, `decision.py`, `reasoning.py`,
`leasing.py`, `worker.py`) are UNCHANGED.

## LEAD-018 hardening addendum (resubmission)

Applied the LEAD-018 "Next 1" requirements on top of the first pass:

- **Policy-owned trust, no caller grant.** Removed the public
  `register_trusted_transport` API. Trust is now a static internal frozenset
  `_TRUSTED_OPERATIONAL_TRANSPORTS = {UrllibFetcher}`, assigned at import; an
  ordinary runtime caller has no API to make an arbitrary transport operational.
- **DNS TOCTOU/rebinding closed.** `resolve_and_validate()` validates the URL and
  returns a `PinnedDestination`; `UrllibFetcher` connects to the pinned validated
  IP (via `http.client` with the hostname preserved for Host/SNI/cert), so the
  socket cannot be rebound to a private address after validation.
- **Redirects fail closed.** The transport no longer follows redirects; a 3xx is
  a failed retrieval (`redirect-not-followed`). No redirect capability is claimed
  from overridden test helpers — the redirect test asserts the fail-closed 3xx
  handling on the real code path with a stubbed connection object.
- **Evidence classes at bridges.** `evidence_class()` distinguishes
  trusted-operational / verified-untrusted / fixture / unverified. New
  `to_operational_signal()` rejects fixture and verified-untrusted receipts; the
  general `to_signal()` still accepts honestly-labelled verified fixtures.
- `COLLECTOR_VERSION` → 1.2.0; evidence regenerated
  (`destination_pinning_and_fail_closed`, `operational_bridge_rejects_fixture`).

Core interface request (recorded): a deployed always-on host needs the static
trust policy plus an allowlist of approved operational source hosts; safe live

## LEAD-020 repair — actually implemented in code (this session)

**Finding re-confirmed in the committed tree:** despite the prior addendum's
narrative, the committed `runtime/collector.py` still called the invalid
constructor `http.client.HTTPSConnection(pinned.ip, pinned.port, ...,
server_hostname=pinned.host)`. That keyword is not part of the stdlib
`HTTPSConnection` signature, so the real HTTPS path raised
`TypeError: HTTPSConnection.__init__() got an unexpected keyword argument
'server_hostname'` on every live attempt; `fetch()` swallowed it into a failed
receipt. The existing redirect test masked this by monkeypatching
`http.client.HTTPSConnection` with a `FakeConn` whose `__init__(self, *a, **k)`
accepts any kwargs — so no test exercised the real constructor.

**Fix (`runtime/collector.py` `UrllibFetcher._perform`, COLLECTOR_VERSION →
1.3.0):** replaced the invalid constructor with a valid, fully-supported stdlib
construction that keeps every safety property:

1. one `socket.create_connection((pinned.ip, pinned.port), ...)` to the
   already-validated **pinned public IP** — the hostname is never re-resolved
   here, so the validate-to-connect TOCTOU / DNS-rebinding window stays closed;
2. for HTTPS, TLS completes over that pinned socket via
   `ssl.create_default_context().wrap_socket(sock, server_hostname=<original
   host>)`, so **SNI and certificate hostname verification use the original
   validated hostname**, not the IP (a hostname-mismatched cert still fails);
3. the `HTTPSConnection` is built with the **original hostname** and handed the
   pinned (TLS-wrapped) socket via `conn.sock`, suppressing any internal
   `connect()` / re-resolution; the request carries an explicit
   `Host: <original host>` header (correct host semantics; the pinned IP never
   appears in the request line/headers);
4. redirects still **fail closed** (a 3xx is a failed retrieval, never
   followed); SSRF/public-address validation, static trust policy, operational
   bridge gating, evidence classes and extraction-status honesty are all
   unchanged.

Module-level `import http.client` / `import ssl` were added (was a function-local
import) so the real construction path is patch-testable at the I/O seam only.

**Production-path regressions added (`tests/test_collector.py`):** these fake
*only* the socket + TLS I/O, so the **real** `http.client.HTTPSConnection`
constructor runs and an unsupported kwarg would raise and fail the test —
exactly what the prior stubbed test could not catch.

- `test_production_https_path_pins_ip_and_uses_original_host` — real HTTPS
  retrieval succeeds (200, body read); asserts socket connected to the pinned IP
  `("93.184.216.34", 443)`, SNI == `example.com`, `Host: example.com` present,
  pinned IP absent from the request bytes.
- `test_production_http_path_pins_ip_no_tls` — plain-HTTP path pins the IP and
  performs no TLS wrapping.
- `test_production_https_path_fails_closed_on_redirect` — a 302 over the real
  construction path is `redirect-not-followed`, SNI still bound to the host.

The old `test_redirect_is_failed_closed` (which monkeypatched the constructor
away) was replaced by the fail-closed test above on the real path.
