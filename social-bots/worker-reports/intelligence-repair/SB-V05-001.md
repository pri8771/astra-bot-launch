## Changes (`runtime/collector.py`)

1. **Trusted-transport gating.** Operational-live provenance is now produced
   only by a *trusted, collector-owned transport*. Trust is granted by explicit,
   auditable registration (`register_trusted_transport` / `is_trusted_transport`)
   — never by a fetcher's own `mode` claim. The receipt records the
   collector-derived `transport_trusted`; `_derive_provenance` returns
   `live-capture` only when `mode==live AND trusted AND status ok`. An arbitrary
   custom fetcher declaring `mode="live"` is downgraded to
   `provenance="unverified-untrusted-transport"` and
   `is_operational_live_evidence()==False`. Trust is keyed on the exact class,
   so a subclass that overrides retrieval does not inherit trust implicitly.

2. **Safe public-destination validation (SSRF defence).** New
   `validate_public_url()` restricts live retrieval to `http`/`https` and rejects
   any destination resolving to loopback / private / link-local / multicast /
   reserved / unspecified addresses (IPv4-mapped IPv6 unwrapped first). Literal
   IPs classify offline (no DNS needed).

3. **Redirect / final-destination validation.** `UrllibFetcher` follows
   redirects manually (auto-follow disabled) and re-validates every hop and the
   final destination before contact, up to `max_redirects`. A public URL that
   redirects to a private/loopback target yields `unsafe-redirect`, not evidence.

4. **`extraction_status` + honesty.** Each receipt carries
   `extraction_status` (`not_attempted`/`ok`/`failed`/`empty`) and an
   out-of-band `extraction_error`. Extraction failures are never placed inside
   `extracted`; downstream consumers gate on `has_usable_extraction()`, so an
   extraction failure can never be used as extracted factual support.

`research.py` and all Core files (`state.py`, `decision.py`, `reasoning.py`,
`leasing.py`, `worker.py`) are UNCHANGED.
