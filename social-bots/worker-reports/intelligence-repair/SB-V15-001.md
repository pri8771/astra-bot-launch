## Scope

Repair of the SB-V15-001 experiment lifecycle engine per INTELLIGENCE_WAVE1 §5:
baseline/treatment must bind to normalized metric observation IDs, metric
semantic/window compatibility must be validated, and learning refs must trace to
the measurements.

## Changes (`runtime/experiment_engine.py`)

1. **Baseline/treatment bind to observations.** New `MeasurementRef` +
   `measurement_from_observation(obs, semantic)` read the value/kind/window from a
   SB-V13-001 `NormalizedObservation`. `design(...)` now takes
   `baseline_observation` (must have a PRESENT primary metric) and `close(...)`
   takes `treatment_observation`. Callers can no longer inject an unattributed
   number; every measurement carries an `observation_id`.
2. **Compatibility validation.** `compatibility(baseline, treatment)` requires:
   both present, same semantic, same `metric_kind` (no snapshot-vs-delta compare),
   and comparable observation windows (duration ratio within tolerance).
   Any mismatch → INCONCLUSIVE with a reason, never a fabricated effect.
3. **Learning ref traces to measurements.** `to_learning_ref` now records the
   `baseline_observation_id` and `treatment_observation_id`, so downstream
   audience/strategy learning traces back to the exact metric observations.
4. Preserved: window-elapsed gating (cannot close early unless safety stop),
   missing-metric → INCONCLUSIVE (never success, never zero), duplicate/overlap
   detection, safety-stop path, and no-learning-ref for inconclusive/stopped.

`pipeline.py` and Core files unchanged.

## SB-V15-001 boundary repair — authoritative bot+persona scoping (this session)

**Gap found in the committed tree:** experiment persistence was **bot-scoped
only**. `save(bot, exp)`, `load(bot, exp_id)`, `load_all(bot)` and
`register(bot, exp)` keyed solely on `bot`; all personas of a bot shared one
`engine/` directory. So a normal persona could `load(bot, other_exp_id)` and
`load_all(bot)` enumerated every persona's experiments — no persona boundary,
and no explicitly-admin whole-runtime reader.

**Repair (`runtime/experiment_engine.py`):**

1. **Persona-partitioned storage.** Each persona's experiments now live in a
   physically separate directory `experiments/<bot>/engine/personas/<persona>/`.
   Isolation is structural (separate path), not a post-hoc filter. Persona
   identifiers are validated via `paths._check` (the same per-namespace safety
   used across the runtime), so a crafted persona string
   (e.g. `../social-b`) cannot traverse out of its partition.
2. **Persona-facing production APIs require bot + persona:**
   - `save_experiment(bot, persona, exp)`
   - `register_experiment(bot, persona, exp, *, reject_overlap=True)`
   - `load_experiment(bot, persona, exp_id)` — returns the record ONLY from that
     persona's partition; another persona's id returns `None` (not visible).
   - `list_experiments(bot, persona)` — enumerates only that persona.
   - `find_overlaps_for_persona(bot, persona, exp)` — overlap check stays inside
     the persona's partition.
   `_require_owner(bot, persona, exp)` refuses to save/register an experiment
   under a (bot, persona) it does not belong to (`PermissionError`).
3. **Whole-runtime reads are explicitly admin/internal:**
   `admin_load_all_experiments(bot)` and `admin_load_experiment(bot, exp_id)` are
   the ONLY cross-persona views, documented as operator/admin-only and never for
   a persona flow. The legacy `load` / `load_all` names are retained as
   documented admin/internal aliases (they route to the `admin_*` readers) so
   existing callers keep working; `save` / `register` / `find_overlaps` remain as
   compat wrappers that route into the experiment's own persona partition.
4. **Retained:** normalized-observation provenance (baseline/treatment still bind
   to SB-V13-001 `NormalizedObservation` ids), semantic/kind/window compatibility
   validation, and INCONCLUSIVE behavior for missing/incompatible measurements —
   all verified through the persona API end-to-end.

**Mixed-persona regressions added (`tests/test_experiment_engine.py`), all via
the production APIs:**

- `test_persona_scoped_roundtrip_requires_bot_and_persona`
- `test_normal_persona_cannot_read_another_personas_experiment`
- `test_normal_persona_cannot_enumerate_another_personas_experiments`
- `test_cannot_save_under_a_persona_you_do_not_own` (PermissionError)
- `test_overlap_detection_is_persona_scoped`
- `test_admin_reader_is_the_only_cross_persona_view`
- `test_unsafe_persona_identifier_is_rejected` (path-traversal defence)
- `test_missing_metric_still_inconclusive_through_persona_api`

  difference with a min-effect threshold and a 2x window-ratio tolerance).
