## What was built

New `runtime/factcheck.py`. Answers "is each material factual claim actually
supported by captured evidence?" rather than the accepted V0.3 "is a URL
present?". Standalone module; `pipeline.py` is unchanged (clean interface for
the lead to integrate at a checkpoint).

### Model
- Claims are classified factual / opinion / creative. Only factual claims are
  evidence-gated; opinion/creative framing is not.
- Support is computed from explicit stance-tagged bindings (supports / partial
  / refutes / unrelated) to **verified** SB-V05-001 capture receipts — never
  guessed. `evidence_ref_from_receipt()` refuses unverified captures.
- Each binding preserves source URL, retrieval timestamp and content hash.
- Statuses: SUPPORTED / PARTIAL / UNSUPPORTED / CONFLICTED / UNKNOWN.
- A binding only counts if the receipt is currently verified AND its content
  hash still matches the hash recorded at review time; a changed hash marks the
  binding stale (`stale-hash-changed`) and invalidates support until re-review.
- URL-present-but-unrelated evidence => UNSUPPORTED (a URL is not support).
- `review_claims()` withholds the candidate if any REQUIRED FACTUAL claim is
  not SUPPORTED or PARTIAL.

## Known limits (explicit, not faked)
- Claim extraction and stance assignment are explicit inputs to this module
  (deterministic, inspectable). Automatic claim mining / NLP stance detection is
  intentionally out of scope — support is bound, not inferred, so no fake
  support can be manufactured. An adaptive extractor can feed this interface
  later behind the same contract.
