## What was built

New collector module that replaces caller-declared provenance with
collector-generated evidence. Provenance is now derived from an actual
retrieval the collector performed, not asserted by the caller.

### Defect eliminated
A caller could previously hand-write a dict and label it `"live-capture"`.
Now the only path to `provenance == "live-capture"` is a `Fetcher` whose
`mode == "live"` actually returning content; the collector — not the caller,
not the fetcher — assigns the timestamp, content hash, status and provenance.
`capture()` takes no `capture_mode`/`provenance` argument, so it cannot be
forged.

### Receipt minimum (all retained)
source URL, canonical source id, retrieval timestamp, retrieval status,
collector name/version, fetcher name, content hash (sha256 of exact bytes),
content byte count, http status, final URL, collector-derived provenance,
error, partial flag, and collector-extracted evidence. No secrets/private
browser state (the live fetcher sends no cookies/auth; a redaction regression
asserts no secret-shaped keys in a receipt).

### Honesty predicates (anti-forgery contract)
- `is_verified_capture()` — True only for `status == ok` with a stable hash.
- `is_operational_live_evidence()` — True only for a live fetcher that
  completed a retrieval; a fixture always returns False.

### Integration (no accepted semantics touched)
`research.py` is UNCHANGED. `collector.to_signal()` bridges a *verified*
receipt into a `research.Signal`, refusing unverified (failed/partial/empty)
retrievals so they can never enter the signal inbox. Signal consumption
ledger, BotState, decision loop, leases, worker lifecycle, reasoning provider
were not modified.

## Tests / evidence
- `python3 -m unittest discover -s tests` -> **54 passing** (was 43; +11).
- New regressions (`tests/test_collector.py`):
  - caller cannot declare live-capture on a fixture; `capture()` rejects a
    `capture_mode` kwarg;
  - a live fetcher yields operational live evidence; an invalid fetcher mode
    is rejected;
  - same source twice -> separate receipts, stable hash;
  - changed content -> changed hash;
  - failed / empty / partial retrieval -> not verified, not operational;
  - receipt minimum fields present; no secrets in a receipt;
  - persistence writes separate durable receipts per capture;
  - `to_signal` requires a verified capture.

## Known limits (explicit, not faked)
- `UrllibFetcher` (the live path) is implemented but not exercised here;
  network is environment-gated and all committed evidence is fixture-based.
  Operational live-capture proof requires an authorized host actually running
  the live fetcher — that remains an external gate, not claimed by this
  artifact.
- Content hashing is over raw bytes; semantic (render-normalized) change
  detection is deliberately out of scope for this artifact.
