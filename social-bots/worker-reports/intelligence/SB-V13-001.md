## What was built

New `runtime/metrics.py` — a truthful cross-platform metric model. Additive:
`analytics.py` (the accepted append-only event log) is unchanged.

### Semantic model
Normalized categories: reach, view, completion, save, share, reply, click,
follow, conversion. Each normalized metric is a `MetricValue` carrying an
explicit `availability`:
- `present` — observed (value may legitimately be 0);
- `missing` — the platform supports it but it was not reported/collected;
- `not_supported` — the platform has no equivalent metric.

**MISSING != ZERO** and **no false equivalence**: raw platform metrics cross
into semantics only through an explicit, versioned per-platform table
(`PLATFORM_MAP`, `NORMALIZATION_VERSION`). An unmapped semantic stays
missing/not-supported rather than borrowing an unrelated metric. The full raw
payload is retained verbatim, and unmapped raw names are kept in
`unmapped_raw` (never blended).

### Retained per observation
platform, source/provenance, account alias, persona, content id, experiment
id, observation window (start/end), collection time, normalization version,
full raw metrics, and per-semantic normalized values.

### Derived metrics
`completion_rate`, `save_rate`, `click_through_rate` each record `formula` and
`formula_version`, and are MISSING (never fabricated as 0) when any input is
missing or the denominator is 0.

### Staleness / trace / aggregation
- `is_stale(max_age_hours)` marks windows past a freshness horizon; an
  observation with no resolvable window end is treated as stale (never fresh).
- `trace_content()` traces one content id from raw metrics up to persona and
  experiment.
- `aggregate_semantic()` groups by platform (never blends across platforms) and
  excludes missing/not-supported from sums instead of counting them as 0.
