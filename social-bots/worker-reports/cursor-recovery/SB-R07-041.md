## Audit summary

Retained the inherited spawn-point fail-closed design from `a73b7b5`
(`ClaudeCodeReasoningProvider` refuses unless a valid canonical manifest is in
force when it would launch the real CLI).

### Evidence-backed defect closed

**Rebinding `_REAL_CLI_RUNNER` un-guarded the real launcher.** The guard keyed
on the rebindable module alias. After `reasoning_cli._REAL_CLI_RUNNER = object()`,
`ClaudeCodeReasoningProvider()` still held the real `_default_cli_runner` but
`_spawns_for_real()` returned False and `available()` was True — a billable
spawn path with no authorization.

**Fix:** guard keys on import-time `_CAPTURED_REAL_CLI_RUNNER` object identity.
The public `_REAL_CLI_RUNNER` alias may still be rebound without weakening the
guard. The `_default_cli_runner` module-global test seam remains exempt when it
no longer points at the captured real launcher (documented limitation).

### Defense-in-depth

`bin/run_worker.py` now refuses live modes (`claude-cli` / `model`) via
`live_route_guard.check` before lease/cycle work (exit 6), matching
`worker_once.py`. Spawn-point remains the backstop for other callers.
