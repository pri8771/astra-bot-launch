## Implementation (`runtime/reasoning_cli.py`)

`ClaudeCodeReasoningProvider` (`provider_id="claude-code-subscription-v1"`,
`adaptive=True`), selected by `SBOTS_REASONING=claude-cli`:

- **Bounded context only** (`_bounded_context`): persona id/kind/name, objective,
  the top signal's id/title/summary/tags/provenance/has_source, pending count,
  duplicate flag, prior-hypothesis count, allowed actions. No secrets, no effects.
- **Prompt** asks for a SINGLE strict-JSON envelope and NOTHING else — **no prose,
  no chain-of-thought**. We never request, parse, or store a reasoning trace; only
  concise rationale, alternatives, uncertainties and evidence refs are kept.
- **Parse** the `--output-format json` wrapper (`result`/`text`/`content`), or a
  bare envelope, into a `ReasoningProposal`. The engine then runs
  `reasoning.validate_proposal` as the single schema gate before scoring.
- **Billing guard:** if `ANTHROPIC_API_KEY` is present the provider is UNAVAILABLE
  and `propose` fails closed without invoking the runner; the value is only ever
  read as a boolean, never logged.
- **Fail closed on every failure mode:** CLI missing (`CLIUnavailable`), timeout
  (`TimeoutExpired`), non-zero exit (not-authenticated / quota / error), empty or
  error/refusal output, invalid JSON, malformed/unknown-action alternative, or a
  proposal the engine rejects on schema — all resolve to no usable proposal, so
  the engine records `BLOCKED_REASONING_UNAVAILABLE`/`_INVALID` and leaves the
  signal pending. **No deterministic fake fallback pretends to be adaptive.**
- A `runner` seam makes the subprocess injectable so tests/CI prove every path
  with zero real model calls and zero spend.

Wired into `reasoning.resolve_provider` as mode `claude-cli`; optional model id
via `SBOTS_REASONING_CLI_MODEL`.

## Tests (`tests/test_reasoning_cli.py`, 16 cases)

- billing guard: API key present → unavailable AND runner never invoked;
- fail closed: CLI unavailable, timeout, non-zero exit, empty output, error
  wrapper, invalid JSON, schema-invalid alternative (blocks via the engine),
  unknown/forbidden action;
- success mapping: wrapper and bare envelope both parse; a valid CLI proposal
  executes end-to-end through the engine (candidate created, unpublished);
- `NO_ACTION` can win; `RESEARCH_MORE` can win;
- materially different context (The Ledger / Tidepool / Switchboard) yields
  materially different recommendations through the adapter;
- command construction: `--print`/`--output-format`/`--disallowedTools` present,
  effect tools denied, `--bare` absent, `ANTHROPIC_API_KEY` stripped from child env.
