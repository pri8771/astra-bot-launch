## Problem (LEAD-015 finding)

> "V03-005 still shares hypotheses and consumed_signal_ids across personas on one
> runtime, allowing cross-persona learning and signal-consumption contamination."

The old `bot_state.json` held `consumed_signal_ids`, `hypotheses`,
`working_state`, `pending_decisions` and `goals` at the RUNTIME level. Because
`social-a` and `cultural-primandir-atman` both run on runtime `social-a`, one
persona consuming a signal hid it from the other, and one persona's hypotheses
changed the other's reasoning novelty (`ReasoningContext.state_summary["hypotheses"]`
counted all runtime hypotheses).

## Repair — explicit two-layer state (`runtime/state.py`)

- **`RuntimeState` (shared, one per runtime — `state/<bot>/bot_state.json`)** now
  holds ONLY runtime-wide facts: process/health `counters`, `recovery`/in-flight,
  `observation_fingerprint`. It no longer carries any persona-private field.
- **`PersonaState` (private, one per persona — `state/<bot>/persona-<id>.json`)**
  holds `consumed_signal_ids`, `hypotheses`, `working_state`, `pending_decisions`,
  `goals`. Methods: `consumed_ids`/`is_consumed`/`mark_consumed`,
  `upsert_hypothesis`/`get_hypothesis`/`hypothesis_count`.
- **Shared captured evidence stays shared and read-only.** The signal inbox
  (`memory/<bot>/signals_inbox.jsonl`) is unchanged; `research.unconsumed_signals`
  is now filtered by the *persona's* consumed ledger, so the same captured signal
  is independently considerable by every persona on the runtime.
- **`decision.run_cycle`** loads both `rt` and `ps`; consumption, hypothesis
  count (reasoning context) and hypothesis writes are all persona-scoped;
  counters/recovery/fingerprint stay on `rt`. Both states are saved inside the
  SB-V03-004 fenced commit.
- **`runtime/isolation.py`** updated: `SHARED_RUNTIME_STATE_KEYS` no longer lists
  consumed/hypotheses; new `PERSONA_PRIVATE_STATE_KEYS`; module docstring
  documents the shared-catalog / shared-runtime / persona-private / persona-
  labeled-artifact layers so docs and code agree.
- **`runtime/worker.py`** lease docstring updated: the runtime lease serializes
  the shared runtime file AND keeps each per-persona file single-writer.

## Safe migration (no silent deletion)

- `RuntimeState.load` detects legacy persona-private keys on an old
  `bot_state.json`, **archives them into `data["_legacy"]`** (never deletes) and
  removes them from the active shared keys.
- `PersonaState.load(bot, persona_id)` migrates the archived legacy values into
  the **default-owner persona** (`persona_id == bot`, i.e. the general persona
  historically owning the runtime's single ledger) exactly once, sources them
  from the archived `_legacy` block or the still-top-level keys of an
  un-persisted file, persists the persona file, and marks the runtime
  `migrated_to_persona=True`. Other personas start clean → no synthetic bleed.
- Migration is idempotent (proven by test).
