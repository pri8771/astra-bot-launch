## Problem (LEAD-015 finding)

> "V04 real adaptive provider remains unverified; deterministic contextual
> provider is explicitly adaptive=false."

The adaptive-required posture existed only as an opt-in env flag defaulting OFF,
so a V0.4 *production* worker could silently run on the deterministic baseline.

## Repair

- **`reasoning.resolve_provider(require_adaptive=None)`** — new optional override.
  None follows the env-driven `adaptive_required()` (default off, for
  tests/diagnostics); True forces the adaptive-required posture regardless of env.
- **`decision.run_cycle(..., require_adaptive=None)`** and
  **`worker.run_one_unit(..., require_adaptive=None)`** thread the posture through;
  the decision record now carries `reasoning.adaptive_required`.
- **`bin/run_worker.py` (the production scheduler payload) defaults to
  `require_adaptive=True`.** A V0.4 production run therefore fails closed to
  `BLOCKED_REASONING_UNAVAILABLE` (signal left pending) when no adaptive provider
  is available — it never falls back to a deterministic provider. Diagnostics may
  opt out with `SBOTS_WORKER_ALLOW_DETERMINISTIC=1` (explicitly not a production
  posture).
- **Schema reconciliation with `REASONING_PROPOSAL_SCHEMA.md`:** `ACTION_VOCAB`
  now includes `CLOSE_EXPERIMENT` (schema allowlist), and a new
  `EXECUTABLE_ACTIONS` names the actions that actually have an effect executor
  (`NO_ACTION`, `RESEARCH_MORE`, `CREATE_CANDIDATE`). `CONTINUE_EXPERIMENT` and
  `CLOSE_EXPERIMENT` validate as proposals but route to a safe
  `blocked_unsupported_action` no-effect — **no future effect executor was added
  just because an action is in the schema**, per the packet.
- Existing proposal validation (bounds, authority-smuggling, recommended-in-
  alternatives, CREATE_CANDIDATE-needs-signal) is unchanged and still the single
  engine gate.
