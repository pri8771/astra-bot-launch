## Root cause (confirmed, not TTL)
`run_one_unit` renewed once, then `run_cycle` wrote state/content/experiment/queue
with **no further ownership check**. If runtime exceeded the TTL, a contender
could take over the stale lease while the original process kept running and
committed afterward. Enlarging the TTL only widens/narrows the window; it does
not make the commit conditional on ownership. Fixed by making commit conditional.

## Design — fencing token + atomic fenced commit
1. **Fencing token (`leasing.py`).** Each lease carries a strictly increasing
   per-task `generation`. Fresh slot → 1; a stale takeover → prior + 1. Monotone
   per task, so a superseded owner can never again match the on-disk generation.
2. **`Fence` (`leasing.py`).** `check()`/`valid()`/`fenced_commit(commit)` verify
   ownership (`lease_id` **and** `generation`) against the on-disk lease *inside
   the same per-task `flock` critical section a takeover's `acquire` uses*. The
   check-and-write is therefore atomic w.r.t. takeover: either this worker is
   still sole owner and the commit runs while the lock is held (no interleave), or
   a takeover already bumped the generation and the commit is refused with
   `FenceLost`, writing nothing. It also refreshes `renewed_at` on a successful
   owned commit (keep-alive for a legitimately long cycle).
3. **All-or-nothing cycle commit (`decision.py`).** `run_cycle(..., fence=...)`
   now PREPARES the outcome and defers **every** durable artifact into one
   `effects` closure — experiment registration, publish-queue entry, success
   analytics, content/hypothesis/action records — committed together with the
   shared `bot_state.json` save and the decision log through a single
   `fence.fenced_commit`. A fenced-out worker advances no state, registers no
   experiment, queues nothing, writes no success receipt, and does not consume
   the signal (the takeover worker decides on it instead). `fence=None` commits
   unguarded, exactly preserving prior behavior for unit tests / dry runs.
4. **Worker lifecycle (`worker.py`).** Builds `leasing.Fence(lease)`, passes it to
   `run_cycle`, stamps `fence_generation` into start/finish receipts, and catches
   `FenceLost` to stand down with a truthful `fence_lost` failure receipt
   (`candidate_succeeded=false`). It never deletes the new owner's lease
   (`release` only removes a lease whose `lease_id` still matches ours).
5. Reconciliation ordering is unchanged and still correct: a stale takeover sets
   `reconcile_required`, and `run_one_unit` reconciles the prior owner's
   (unpublished) effects **before** doing eligible work.

## Host / filesystem scope (explicit — no over-claim)
- **Guaranteed:** one **POSIX host**, one **local filesystem** (`fcntl.flock`);
  the kernel frees the lock if the holder dies.
- **Not proven — native Windows:** `FLOCK_AVAILABLE=False`; the atomic-replace
  fallback does not provide the flock critical section, so the strong
  active-cycle fence is **not** claimed there (needs e.g. `LockFileEx`, separately
  proven).
- **Not proven — cross-host / network FS:** `flock` over NFS/SMB and across
  machines is unreliable; multi-host fencing needs a shared authority
  (lease service or DB compare-and-set), out of scope here and not assumed.
  The Linux always-on host asserts `FLOCK_AVAILABLE`.

## Known limits (explicit, not faked)
- `renew` still permits a stale-but-not-yet-superseded owner to refresh; that is
  intentional (aging without a takeover does not transfer ownership). The safety
  property that matters — no two committers — holds because a takeover is the only
  way another worker gains ownership, and that bumps the generation the fenced
  commit checks.
- Concurrency proven with threads + a barrier (syscalls release the GIL); the
  guarantees are filesystem-level so they extend to processes on the same host,
  but that specific cross-process claim is not separately scripted here.
- SB-002 always-on host recurring liveness is still unproven (separate artifact);
  lease/fence correctness does not substitute for host-side recurring receipts.
