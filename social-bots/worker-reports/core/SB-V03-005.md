## Isolation design choice
**Logical isolation** (the packet's explicitly-permitted alternative), chosen
because (1) shared runtime state must stay shared and serialized, and (2) the
experiment/content stores are Intelligence-owned (`pipeline.py`); a physical
per-persona layout would be a cross-lane storage change. Two disjoint classes:

- **Shared runtime state** — `state/<bot>/bot_state.json` (consumed-signal ledger,
  hypotheses, counters, recovery, observation fingerprint) + the runtime signal
  inbox. Shared on purpose (evidence captured once per runtime, consumed once per
  runtime). Single-writer via the runtime lease (`cycle:<bot>`) + the active-cycle
  fence (SB-V03-004): only the fenced owner commits it.
- **Non-shared persona data** — content, experiments, publish queue, analytics
  events, action/decision records — logically isolated inside the runtime's
  append-only stores by: (a) a mandatory `persona` field on every record;
  (b) persona-derived, collision-free ids (`content_id=H(persona:move:signal)`,
  `content_key=H(persona|signal|move)`, `experiment_id="exp-"+content_id`);
  (c) persona-specific reads only through `runtime.isolation` filters.

Architecture (`ARCHITECTURE.md`) and the `state.py` docstring were rewritten to
describe exactly this, so docs and code now agree.

## Known limits (explicit, not faked)
- Isolation is logical, not physical: all of a runtime's personas share one
  filesystem tree per store. Contamination is prevented by labels + collision-free
  ids + filtered reads, not by directory separation. If physical per-persona
  namespaces are ever mandated, that is a cross-lane change to `pipeline.py`
  storage and `paths.py` and should be assigned explicitly.
- `runtime.isolation` reads Intelligence-owned stores (`pipeline.publish_queue`,
  `analytics.events_for`) but does not modify their layout — no cross-lane edit.
- Host/filesystem scope identical to the lease/fence: single POSIX host, single
  local filesystem. No public/external effect; publish stays disabled/unauthorized.
