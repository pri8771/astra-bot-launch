# Codex multi-project operating contract

## Role: coordinate work, do not collapse three products

The owner wants one Codex session to manage Bots, Jobs and Swarm. Codex coordinates status, artifact selection, reviews, blockers and available workers across separate repositories. ChatGPT remains the engineering/product lead and final artifact acceptance authority under the currently verified contracts. Codex can independently reproduce tests and recommend acceptance; it must not impersonate a ChatGPT review or accept its own implementation.

The current instruction is not a new autonomous service deployment. Do not build another orchestration platform, merge the repositories, share product databases/memory, or require Bots/Jobs to run through Swarm. Coordination files may reference sanitized artifact metadata across projects. Product data, secrets, approval ledgers, runtime storage and business identities remain separated.

## First sweep and work selection

Perform one fresh Git/ownership/evidence sweep across all three repos. Read current scope before deep code. For each record exact coordination SHA, actual source SHA, owner/host/session, active artifact, tested evidence, missing live predicate, genuine gate and smallest permitted next task. Do not call an unavailable repo done or guess from history.

Review an outstanding submission before asking for new code. Order actual runnable work by enabled-path safety defect, required live-proof blocker, integration correctness, then remaining in-scope feature work. Use deterministic round-robin to break ties so no project is starved. A blocked project does not block the others. All three stop development at accepted live V1.7; already-authorized operation may continue only under its own valid scope.

Tasks stay in their project's existing queue. A shared session table is an index of current work, not a second editable milestone registry. Never mark later versions complete to free an earlier build. Safe provisional engineering uses only the explicit allowance in that project; an unmet review hold or live gate still blocks the corresponding action.

## Single implementation owner per repository

Fable is currently assigned as implementation worker in all three project contracts. Those names do not prove three active model processes exist. Discover actual sessions and local work before acting. Codex may coordinate and review immediately; it may implement an already-released artifact only after a documented clean ownership handoff consistent with that repo. Preserve source and issue an explicit task assignment; do not silently become a second integrator.

A handoff identifies repository, actual source/head, current task, allowed paths, task/heartbeat owner, pending changes, tests and next action. If Fable is still writing those paths, do independent read-only review or another safe project. A stale timer, missing periodic Bots comment or a branch named cursor is not authority to kill or steal work. Do not forge a worker ACK. If a worker transport is not available, say so; a Git instruction alone does not wake it.

## Git and workspace boundaries

Use separate Git roots and explicit work directories per command. Maintain a local path map; paths are discovered, not guessed from historical Downloads names. Keep coordination worktrees separate from application worktrees. Jobs main is coordination truth but the prepared candidate is not automatically merged/accepted. Swarm coordination can contain older app code: use git show or a coordination worktree, never replace source with that snapshot.

Before a write verify repo identity, branch, expected base and clean/dirty status. Preserve new pushes, local changes and untracked evidence. Commit small artifact-prefixed changes; keep code and evidence refs distinct. No force-push/reset, destructive cleanup, main merge or public release without appropriate explicit permission. A multi-repo handoff contains a map of per-repo SHAs, never one SHA pretending to identify all repositories.

Do not expose credentials through remote URLs, git config dumps, .env files, provider logs or raw mailbox/profile data. Report sanitized aliases/digests. Nothing in this hub transfers a GitHub/Google/provider credential from one project to another.

## Authority and external actions

Current owner directives override obsolete scope, not external-action safety. Live tests require actual project-specific grants. Bots' consumed canary allowance does not cover a new model batch; Jobs' test identity does not permit an employer application or mailbox scan; Swarm's approved external GitHub checkpoint does not authorize Bots posting.

Prepare one precise gate dossier across projects, keeping separate scoped records: project, artifact, actual action, identity/destination, inputs, provider, cap, expiration, zero-new-spend posture, owner approval reference and lead manifest. Read available approved metadata first. Do not repeat questions already resolved in source. Stop only the gated action; continue permitted work elsewhere.

No new spend/PAYG/paid fallback, public posting, employer submission, recruiter email, calendar mutation, destructive external operation, CAPTCHA/MFA evasion, unauthorized model batch or credential disclosure. No fabricated resume facts, fake engagement or invented operational evidence. Lower-cost subagents require actual availability, current permission and proper budget accounting; do not assume marketing model names or effort settings exist.

## Evidence and reporting

Separate IMPLEMENTED, worker-reported tests, independently reproduced engineering, integrated production-path evidence and lead-accepted LIVE milestones. A real source fetch proves only source capture. Hashes prove byte correspondence, not an honest origin by themselves. A screenshot, successful API request, model-written result or passing fixture cannot prove its missing downstream stage.

Record command, candidate/config/environment, times, input/output hashes and discovered/pass/fail/error/skip counts. No adding test counts across different candidates to imply one full-suite run. Preserve original failed/uncertain attempts and use a new authorized run rather than rewriting history. Use native source citations/ref paths in review records.

Keep context small: active card, targeted diff, exact symbol, compact checkpoint. Use already-supported lower-cost subagents for mechanical isolated tests/search/docs; keep security, concurrency and integration review with a capable reviewer. A subagent's independence is described truthfully. Checkpoint on context exhaustion with an exact next action. A stopped chat does not continue until a real authorized process invokes it.
