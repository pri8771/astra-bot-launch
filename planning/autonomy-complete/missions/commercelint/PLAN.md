# CommerceLint complete product and autonomy plan

CommerceLint's outcome is legitimate verified net cash from useful ecommerce diagnostics. The free scanner/CLI, scoped $49 audit, agency service, consent-aware measurement, operator and portfolio mount are assets to extend. A release is useful before payment qualification; paid fulfillment and business validation require their own evidence.

The customer journey is discovery through a relevant guide/CLI/agency page -> pasted HTML or permitted public scan -> prioritized evidence and repair suggestions -> saved/exportable report -> explicit audit request -> scope/capacity agreement -> eligible invoice/payment -> independently checked defect pack -> verified delivery -> one clarification -> observed repeat need or separately scoped remediation/agency work. Free findings screen field presence; they cannot promise selected-variant, live checkout or ranking correctness. Acquisition and paid offers remain hypotheses evaluated against this journey.

Implement in the canonical product repository. Proposed paths in task cards are future ownership reservations, not assets claimed to exist. CL-01 qualifies current release evidence. CL-02 improves scanner continuity while CL-04 builds offer/fulfillment and CL-06 measurement/acquisition, with their stated dependencies. CL-03 provides durable request/delivery. CL-05 is a conditional merchant capability. CL-07 uses the existing portfolio owner and serializes the shared destination with BF-12; it does not edit another venture or replace production workflows. Existing operator-owned state is mutated only by the admitted owner. No worker is interrupted by this plan.

The runtime integration is split into concrete adapters. CL-08 binds existing hourly/growth/lead triggers to authoritative event cursors, atomic claims and fencing; GitHub Actions concurrency protects only its current scope. CL-09 consumes owner revisions/questions and immutable Jira/documentation outboxes. CL-10 grounds business decisions in observations and declared experiments. CL-11 qualifies Windows process cleanup, recovery, privacy, alerts and enforced resource caps. CL-12 proves repeated real cycles. The existing operator is kept as the one effect owner unless a recorded destination-reconciled, fenced handoff is accepted. A second idle scheduler is not an implementation strategy.

Public code stores templates, validators and sanitized aggregate evidence. Private runtime storage holds customer conversations, accepted scopes, fulfillment evidence and financial receipt references with retention/deletion. The existing private CRM is reused after scoped access verification; its private identifier and messages never enter this repository. Browser-only saved scan reports need explicit retention/delete behavior. Third-party URL retrieval is a declared data boundary and paste mode works without it. Publisher/payment/email adapters require their own account scopes and receipts; discovery of a credential reference cannot expand permissions.

Observation events include a received request, completed scan aggregate, accepted scope, delivery due time, source/analytics change, settled cash and owner direction. Each creates or updates a stable job only when its source revision changes. A deterministic timer checks next_check_at and fingerprint before reasoning. One active pilot experiment is the proposed default, despite the older source allowing two; expansion requires capacity and noncontamination evidence. The initial pilot compares a better defect-to-repair/offer path or an agency sample based on current observed bottleneck. The admitted protocol defines a primary metric, denominator, relevant exposure threshold, window, stop rules, costs and alternative. Do not recycle a historical visitor threshold as fact.

A complete cycle observes actual allowed evidence, persists a decision/protocol and writer admission, executes one eligible action, verifies the receiving page/comment/payment/delivery, records the result, evaluates the declared window and chooses a reviewed next candidate or a justified wait. Repeat at least twice without a fresh owner launch instruction. Low traffic may yield inconclusive; payment unavailability may leave free utility/acquisition autonomy qualified and money capability pending. Revenue is never inferred from launch, generated guides, visits, claims of operator health or synthetic requests.

Owner direction example: "Focus on agencies that need recurring QA" is recorded and acknowledged by revision, reorders unstarted proposals, and preserves previous experiments. "Pause acquisition" blocks pending sends at the safe boundary; a submitted comment/payment is reconciled rather than assumed canceled. A missing storefront URL produces one persisted question and resumes only that request after a validated answer. Shared writer/mirror outages queue immutable outboxes and block only operations whose required experiment admission is absent.

Acceptance must exercise a crash before submission and after destination acceptance but before acknowledgement; response/comment/charge keys survive restart and destination lookup returns one original effect. Kill a Windows parent with a child process and verify complete tree cleanup. Restore encrypted state, reject stale owner tokens and show a Mac-disconnected interval with bounded Windows work.
