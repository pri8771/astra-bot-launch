## Compact documentation standard

Each discussion should leave four maintained documents in the actual source repository or a clearly mapped planning folder: `PRD.md` (user/business goal, scope, success and next release), `ARCHITECTURE.md` (existing components, reuse, data/permissions, host/cloud deployment), `TASKS.md` (dependencies, existing Jira mapping, acceptance and review), and `STATE.md` (verified current truth, open decisions, next action and evidence links). Reuse equivalent existing files instead of creating duplicates.

Estimates come from explicit planning; actual effort/results come from receipts. Shared policies are referenced, not copied. Cursor can project reviewed definitions into Jira through the designated writer; a file or discussion is not Jira readback, task admission or completed development.
